# 查询契约格式（contract-format）

查询契约是契约查询模式的输入，结构化 JSON。契约 MUST 遵循本格式；对话派生模式先产出同结构契约再执行（两模式共享同一执行路径）。机读权威为 `assets/schema/contract.schema.json`（JSON Schema，语言无关，单一权威副本）；本文件为其人读说明，二者字段须一致。

## 结构

```json
{
  "project": "<项目存储位置，缺省为宿主当前工作目录>",
  "repository": "<事实仓库存储位置，缺省以环境变量或固定路径补齐>",
  "version": "<来源项目版本，缺省为当前版本>",
  "facts": {
    "<层级>": ["<事实类型>", "..."]
  }
}
```

- `project`：目标项目存储位置。缺省时以宿主当前工作目录补齐，并在输出中标注该缺省。
- `repository`：事实仓库存储位置（SFRS）。缺省时以缺省来源（环境变量或固定路径）补齐，并在输出中标注 `repository_defaulted: true`。
- `version`：来源项目版本。缺省为当前版本；Git 仓库取当前 commit，非 Git 本地文件夹视为始终当前版本。请求版本缺失时回退当前版本，输出标注真实版本与 `version_fallback`。
- `facts`：所需事实的节点定位。以层级名（项目/模块/符号/事实）为键，值为该层的请求列表：列表项为字符串（事实类型，定位该类型节点本身）或对象 `{fact_type, path?}`（节点定位 + 可选续查路径，path 为上一级返回的下一级节点引用序列）。返回粒度按查询节点下一级——每个下一级节点标注是否为子树节点，子树内容由消费方续查逐级获取；未被请求的子树不返回、不构造。

## 校验规则

1. 契约所引用的事实类型 MUST 属于可提供事实目录（`fact-catalog.md`）；目录外引用判为"超出范围"，在输出中以 `out_of_scope` 显式声明，MUST NOT 编造或模糊返回。
2. `facts` 未声明某层时，该层不提取、不输出（最小化）。
3. 目录外引用与"目录内但项目中缺失"的 gaps 分列声明，不得混同。

## 缺省处理示例

- 契约含 `"project": "/path/to/repo"` → 以该位置为唯一项目根提取。
- 契约缺 `project` → 采用宿主当前工作目录，输出中标注 `project_defaulted: true`。
- 契约缺 `repository` → 采用缺省来源（环境变量或固定路径）补齐，输出中标注 `repository_defaulted: true`。
- 契约缺 `version` → 采用来源项目当前版本，输出标注真实版本。

## 完整契约示例

```json
{
  "project": "/home/user/my-project",
  "repository": "/var/lib/sfrs",
  "version": "a1b2c3d",
  "facts": {
    "项目": ["项目用途/领域", "模块划分", "入口"],
    "模块": ["模块职责", "模块间依赖"]
  }
}
```

该契约只请求项目层与模块层的上述事实，输出 MUST NOT 包含符号层、事实层信息。
