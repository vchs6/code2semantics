# Proposal（信息获取工具调研）

## Why

构造语义事实集构造前，需要先知道：**它能够使用哪些工具、Skill、或由AI代理来提取/获取项目的哪些原始信息**。本变更的触发点是在设计提取器时，要先基于构造语义事实集的需要，开展这些原始信息提供者的生产能力调研。只有先形成工具清单，才能基于它们来确定信息获取方式和实现原始信息解析器。

## What Changes

- 以确定的项目信息需求清单为输入，产出**生产能力调研报告**（文档工件，非代码变更）：
  - 逐信息需求调研能生产它的宿主工具、本机 Skill 与智能体形态；
  - **为每个纳入调研的工具记录画像**：规模分级（小型 / 中型 / 大型——小型＝单一职责、轻量、输出结构简单；大型＝重基建平台、输出庞杂、需多解析器分流；介于两者为中型）与**支持的编程语言列表**（多语言通用工具须显式列出，作为覆盖矩阵选型策略的判定输入，目的：减少解析器数量）；
  - 构建"信息需求 × 生产者"覆盖矩阵，给出 可完成 / 部分可完成 / 不可完成 判定与证据；**矩阵生产者列为选型策略执行后的结果**（2026-10-22 定策，目的：减少解析器数量——每个接入工具至少对应一个解析器）：同一信息需求存在多个可完成生产者时，按 (a) 小型工具优先（单一职责、轻量、输出结构简单）、(b) 多语言工具优先（语言无关通用，同一解析器可跨语言复用）择优；语言专属工具仅在多语言工具不可判定或语义不足时引入；(a)(b) 均不区分时按生产阶梯（工具直出 → Skill → 智能体）取最确定者。矩阵之外不另行承载选择决策——下游（构造器）只查矩阵、不回溯本报告择优；
  - 汇总差距清单，作为提取器实现对弱覆盖信息的处理依据与 fact-catalog 生产方式回填的依据。
- 报告落盘至变更目录 `research/semantic-tooling-survey.md`。
