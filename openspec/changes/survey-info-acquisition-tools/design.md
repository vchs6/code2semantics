# Design

## Context

本变更是纯调研工件（`skip_specs: true`），不改变任何系统行为。调研对象是**信息获取能力**——构造语义事实集需要提取/获取项目的哪些原始信息，以及每项信息由什么工具、Skill 或 AI 代理生产。触发点在设计提取器时：基于构造语义事实集的需要开展本调研，先形成工具清单，再据此确定信息获取方式和实现原始信息解析器。事实需求本身不在本变更范围内（归 `survey-semantic-fact-requirements`）。

本机宿主（当前为 AtomCode）可用的第一手素材：

- 已安装 Skill 清单（系统可见），语义相关者：`rust-symbol-analyzer`（LSP 符号）、`semantic-adversarial-review`（语义条目对抗审查）、`knowledge-base`（迁移知识库/证据治理）、`migration-orchestrator`（迁移规划）等；通用辅助：`ast_grep`/`grep`/`find_references`/`trace_callers`/`blast_radius` 等代码智能工具。清单与能力面（代码探索、调用图、子代理委派）在各代理环境中均有对应物，调研结论按能力面归类，不绑定单一宿主。
- 宿主工具侧能力：LSP 符号读取、AST 模式搜索、调用图追踪（caller/callee/chain）、影响面估算（blast_radius）、文件依赖图。

## Goals / Non-Goals

**Goals:**

- 以确定的项目信息需求清单为输入，逐信息需求映射生产能力——每项信息由哪些工具/Skill/智能体生产，给出 可完成 / 部分可完成 / 不可完成 判定与证据，回答"谁来生产"。
- 输出"信息需求 × 生产者"覆盖矩阵与差距清单，直接支撑信息获取方式确定、原始信息解析器实现与 fact-catalog 生产方式回填。

**Non-Goals:**

- 不归纳事实需求（需要哪些事实归 `survey-semantic-fact-requirements`）；不产生信息需求清单（那是提取器设计的产物，本变更以其为输入边界）。
- 不实现任何 Skill 或工具代码；不代替 epic 做设计决策。
- 不评测运行时性能，只做能力边界分析。
- 不覆盖本机未安装且无法通过文档确认的工具（仅可引用公开资料并标注为二手信息）。

## Decisions

1. **生产能力映射以提取器确定的信息需求清单为边界**。信息需求集合在调研开始时即固定，本变更不新增、不删减；发现清单遗漏时记入差距清单并回溯确认，不在本变更内扩张。备选（调研中随工具发现补充信息需求）被否——会倒置需求与能力。
2. **生产能力映射采用"信息需求 × 生产者"矩阵**，判定等级取三档：可完成（现有能力覆盖）、部分可完成（需组合或多步编排、或输出不满足契约结构）、不可完成（能力缺失）。每格附一行证据。
3. **证据要求**：每条判定附一行证据（工具名/能力来源/文档出处）；公开资料标注"二手"。
4. **报告用中文撰写**，与 config.yaml 的 zh 约定一致；SHALL/MUST 等结构关键词保留英文。
5. **调研有度（有界调研）**：以"够支撑信息获取方式确定与解析器实现"为准出条件，不做穷尽——①范围有界：只覆盖信息需求清单所列项；②深度有界：一手（本机环境）优先，二手资料每信息需求至多 2 个来源、标注即可，不深挖；③止损规则：某信息需求找不到生产能力时记入差距清单即止，不得转为无限扩源。理由：调研是设计输入不是交付物本身，边际信息低于成本即停。备选（穷尽式盘点）被否——成本失控且多数结论不进入设计。

## Risks / Trade-offs

- [本机 Skill 清单可能随安装变化] → 报告注明调研基准日期与来源为当前宿主环境。
- [二手资料与实际版本行为不一致] → 二手结论单独标注，不作为"可完成"判定的唯一依据。
- [提取器实现与调研结论出现偏差] → 覆盖矩阵与差距清单引用清单版本与基准日期；信息需求演进走提取器设计的复评机制，本报告随之更新。
