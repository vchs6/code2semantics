# Proposal（语义事实构造器）

## Why

`layered-semantic-facts` Skill 已落地事实的查询契约与输出契约，`add-semantic-fact-repository`（SFRS）已定稿事实的存储与取回，但**事实的生产端尚无确定性载体**——当前“事实由 Skill 产生”依赖代理在会话中按文档即兴提取，不具备“精确、可重复、一致”所需的可确定性。需要在事实进入仓库之前，有一个独立、确定、按契约构造语义事实集的组件，把“生产”从“编排/归纳”中分离出来。

## What Changes

新增**语义事实构造器**（Semantic Fact Constructor）：一个独立的、确定性的、以查询契约为输入、以输出契约事实集为输出的构造组件。构造器只构造事实集，不落库、不编排除自身职责外的流程；其职责边界以本提案为限。

### 核心定位

**构造器是“源码 + 事实集契约 → 语义事实集”的确定性生产组件，是事实生产端的唯一确定性载体。** 它接收事实集契约（要哪些事实）与项目位置，经由“合成分析 → 生产者选择 → 调用执行 → 输出解析 → 事实合成”的流水线产出符合输出契约（output-schema）的语义事实集；`layered-semantic-facts` Skill 负责编排构造器并提交事实集入库（SFRS），构造器自身不感知存储。

### 主要提供

1. **按契约构造**：接收结构化查询契约，产出契约要求的事实类型与字段；未要求的层与字段 MUST NOT 出现（最小化，与 Skill 的封闭世界规则一致）。
2. **合成分析**：依据事实集契约要求的事实类型，确定构造各事实所需的下层项目信息；该“事实类型 → 信息需求”的分解为确定性分析，其结果固化为**信息需求清单**（本变更交付物）。分解按信息需求去重：不同事实所需的同一信息在清单中聚合为同一条目，作为后续批量获取的聚合单位。
3. **生产者选择**：按信息需求，查阅**生产能力矩阵**（独立变更 `add-semantic-capability-matrix`，构造器只读），确定各信息需求的生产者与其调用方式。选择以信息需求为粒度查矩阵；同一工具可服务多个信息需求，生产者链按工具聚合。矩阵条目的生产者已由生产能力调研按选型策略择优后写入（小型工具优先、多语言工具优先，见 `survey-info-acquisition-tools` 提案），构造器只依矩阵条目取生产者链，MUST NOT 回溯调研报告另行确定工具。生产策略见核心设计原则 1（确定性优先、语义理解 AI 参与）；分层归属由生产能力调研回填，构造器不预设。
4. **调用执行与调度监控**：由**执行器**负责工具的调度与监控——进程生命周期、超时、输出捕获与完整性校验、重试与降级、结构化异常报告，保证得到工具输出或以结构化方式报告异常。同一轮构造内，事实所需信息可由多个工具生产，但每个工具仅调用一次：构造器将本轮信息需求经矩阵展开为生产者集合并按工具聚合，逐工具执行一次，其信息数据项按信息需求路由至各事实合成，MUST NOT 对同一工具按事实类型重复调用。
5. **输出解析**：将各工具的原生输出经**解析器**（外部独立组件，构造器只调用、不实现）转换为符合**信息契约**的项目信息数据项。
6. **事实合成**：由项目信息数据项合成语义事实；每条事实 MUST 附源码证据定位（文件:行号范围），证据自信息数据项传递，全链不可断裂。
7. **缺口显式**：契约要求的事实若其信息生产者尚不可用（无生产者、解析器未实现、工具执行失败），进 gaps 并标注原因，MUST NOT 编造填充。
8. **代理归纳生产路径（兜底）**：对"无工具直出生产者、或仅有语义归纳类生产者（项目分析 Skill / 智能体兜底）"的信息需求，构造器 MUST NOT 自行即兴归纳，而以结构化**归纳请求**（induction request，含事实类型、fact-catalog 字段、信息需求指导）随输出显式暴露，交由声明的兜底生产者归纳；归纳结果经统一的**归纳并入接口**（inducer）按契约回传、校验（仅目录内类型、证据绑定）后并入事实集。该路径的请求结构、调用约定与透传/拒收规则为设计阶段产出，本提案只声明其存在与职责归属，不预设实现细节。

### 职责边界

属于构造器：事实集契约校验；合成分析与信息需求清单维护；查矩阵选生产者；工具调度与监控（执行器）；调用解析器取信息；由信息合成事实；结构化归纳请求的产出与归纳结果的按契约并入；缺口与异常的结构化表达；输出符合 output-schema 的事实集。

构造器 MUST NOT：生产或维护能力矩阵（只读）；设计或实现解析器（只调用）；落库或对接 SFRS（事实集由 Skill 提交）；对语义归纳类信息自行即兴归纳——必须以结构化归纳请求显式交接给声明的兜底生产者，不得静默跳过或自行编造。事实的下游使用（迁移规划、语言映射、代码生成）不在本构造器职责内。

### 核心设计原则

1. **事实优先复用、证据按需获取；确定性优先、语义理解 AI 参与**：事实优先复用（命中仓库即返回，不重复分析）、证据按需获取（最小化，仅取契约要求的层与字段）。能确定性提取的事实（契约校验、合成分析、查矩阵选链、工具调度、输出解析、事实合成）MUST 实现为确定性程序，不交给 AI 在运行时按文档描述重建；需要语义理解的事实（无确定算法可依的归纳类）由 AI 基于充分证据分析。所有结果结构化、可追溯（证据 file:line 回链），并依据事实类型实施验证（确定性事实用确定性测试；归纳事实用证据回链 + 契约校验）。三个目标：减少不必要的重复分析；尽量降低 AI 的上下文与 Token 消耗；避免把 AI 的推断直接当成确定性事实。
2. **契约消费**：以查询契约（contract-format）与输出契约（output-schema）为输入输出权威；信息契约（项目信息数据项 schema）为解析器与事实合成的中间枢纽，其机读 schema 为语言无关权威（JSON Schema）。
3. **能力外置**：构造器的可构造范围 = 生产能力矩阵中“判定可完成且解析器已实现”的集合，随矩阵播种与解析器落地而渐进成长；冷启动时矩阵为空、零解析器，构造器仅可运行编排，产出信息需求清单。
4. **纯消费方**：对矩阵只读、对解析器只调用、对存储零感知，自身行为可独立于外部工件而测试（给定矩阵与解析器桩，编排逻辑可判定验证）。

### 结构决策归属

信息需求清单的内容、信息契约的结构与字段、生产阶梯的分层归属、兜底生产路径的交互契约（归纳请求结构、归纳并入接口、透传与拒收规则）、工具链映射的配置形态，均为设计阶段或生产能力调研的产出（分别见 design.md 与 `survey-info-acquisition-tools`），本提案不预设其结构细节。

## Capabilities

### New Capabilities

- `semantic-fact-constructor`：语义事实构造器——按契约构造语义事实集：合成分析、生产者选择（只读能力矩阵）、工具调度监控（执行器）、输出解析（调用外部解析器）、事实合成、代理归纳请求与并入（兜底）、缺口显式表达，输出符合输出契约的语义事实集。

### Modified Capabilities

（无。）

## Impact

- 新增：语义事实构造器组件及其与能力矩阵、解析器、查询契约/输出契约的衔接接口；信息需求清单（解锁 `survey-info-acquisition-tools`）；代理归纳生产路径的请求与并入接口（兜底生产者交接）。
- 关联但不在本变更修改：能力矩阵（`add-semantic-capability-matrix`，构造器只读）；解析器（独立提案）；SFRS（构造器不直接对接，Skill 提交入库）；`layered-semantic-facts` Skill（职责表述由“产生事实”微调为“编排构造器并提交事实集”，该表述调整在 Skill 侧变更中处理，本变更不改 Skill 文件）。
- 影响范围：为 `layered-semantic-facts` Skill 提供确定性的事实生产后端；为生产能力调研提供封闭输入（信息需求清单）。
