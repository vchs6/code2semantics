# Design

## Context

现状（均已核实落盘）：`layered-semantic-facts` Skill 已交付契约查询与对话派生两种模式，其事实边界、契约格式与输出 schema 由 `skills/layered-semantic-facts/references/` 下四份文件定义（`fact-catalog.md`、`contract-format.md`、`output-schema.md`、`report-template.md`），目前仅有 Markdown 形态、无机读权威。事实集为一次性会话产物，事实的生产由 Skill 在会话中按文档描述执行，无确定性载体。SFRS（`add-semantic-fact-repository`）已定稿事实存储，但同样无事实生产后端。生产能力调研（`survey-info-acquisition-tools`）已执行完成（`research/semantic-tooling-survey.md` 落盘，6/6），能力矩阵（`add-semantic-capability-matrix`）与本变更同批规划、构造器只读。

依据产物（config design 规则：只固化有调研支撑的结论，逐条引用）：

- 事实集需求清单（`../../survey-semantic-fact-requirements/research/semantic-fact-requirements.md`，下称“事实清单”）：四层结构（项目→模块→符号→事实）与各层事实类型/字段；证据定位格式“文件:行号范围”。
- fact-catalog（`skills/layered-semantic-facts/references/fact-catalog.md`）：消费方可查询事实的封闭边界与各层字段。
- contract-format 与 output-schema（同目录）：查询契约与事实集的结构、校验规则（最小化、gaps 与“超出范围”分列）。
- 定稿 proposal（本变更 `proposal.md`）：构造器定位、流水线、职责边界——行为需求以其为唯一依据，本设计不重复论证。
- 生产能力调研报告（`../../survey-info-acquisition-tools/research/semantic-tooling-survey.md`）：覆盖矩阵与差距清单，为生产阶梯分层归属的依据。

## Goals / Non-Goals

**Goals:**

- 设计构造器的确定性流水线（合成分析 → 生产者选择 → 调度执行 → 输出解析 → 事实合成），逻辑词汇沿用 fact-catalog 与 output-schema，不创设新层级或新字段。
- 确定构造器与外部工件的接口边界：只读能力矩阵、只调用外部解析器、不感知存储。
- 固化可脚本化流程的实现形态（确定性程序 + 可判定验证），并声明信息需求清单为本变更的确定性交付物。

**Non-Goals:**

- 不回填 fact-catalog 生产方式/弱覆盖处理，不编制能力矩阵内容（属 `survey-info-acquisition-tools` 与 `add-semantic-capability-matrix`）。
- 不设计或实现解析器（独立变更 `add-info-parser`）。
- 不修改查询契约与输出契约语义；不改 Skill 提取行为；不落库。

## Decisions

1. **确定性流水线为单一程序（规则 7）**：契约校验、合成分析、查矩阵选链、工具调度、输出解析、事实合成、缺口表达均为可脚本化的确定性处理，实现为常规程序（Python 编写），MUST NOT 交由 AI 代理在运行时按文档描述执行。验证方式：pytest 场景覆盖——每个 spec scenario 对应至少一个测试，矩阵与解析器以桩（stub/fake）注入，编排逻辑可判定验证。备选（代理按文档执行构造）被否——不具备“精确、可重复、一致”所需的可确定性。依据：AGENTS.md 原则 7、proposal「核心设计原则」1。
2. **输入输出契约复用既有契约语义**：构造器的输入是查询契约（contract-format），输出是 output-schema 事实集；两者的结构约束与最小化、gaps/out_of_scope 分列规则即为构造器的构造与校验规则，构造器不另立标准。依据：contract-format「校验规则」、output-schema「约束」、spec「按契约构造语义事实集」。
3. **逻辑词汇沿用分层语义事实模型**：合成分析的目标事实类型与字段、事实合成的词汇，沿用事实清单四层结论与 fact-catalog 各层字段，证据定位沿用“文件:行号范围”。本设计不创设新层级或新字段。依据：事实清单「分层结构（分析结论）」、fact-catalog 各层表格、proposal「结构决策归属」。
4. **合成分析产出信息需求清单为确定性交付物**：合成分析以 fact-catalog 事实类型字段为封闭输入，确定各事实所需的下层项目信息，产出“事实类型 → 信息需求”的分解清单；该清单是确定性程序的输出（非代理即兴归纳），同契约必同清单。它同时是 `survey-info-acquisition-tools` 的封闭输入（解锁调研）与能力矩阵行维度的来源。依据：proposal「主要提供」2、survey-info-acquisition-tools tasks.md 第 1 条。
5. **能力矩阵只读、解析器只调用**：生产者选择仅查阅能力矩阵（判定可完成且解析器已实现的条目）；输出解析仅经统一注册接口调用外部解析器。构造器不生产/修改矩阵、不实现解析器。依据：proposal「职责边界」、spec「按能力矩阵选择生产者」「输出解析经外部解析器」。
6. **执行器为构造器内部确定性组件**：工具调度与监控（进程生命周期、超时、输出捕获与完整性校验、重试降级、结构化异常）由执行器承担，行为由矩阵条目声明的调用剖面（命令/超时/重试/输出类型→解析器映射）驱动，无认知决策，留在构造器边界内；实现为边界清晰、契约单一的模块——输入为调用剖面、输出为输出数据流或结构化异常，不依赖矩阵、编排核心、解析器与事实合成。抽离为独立组件的前提是出现第二个真实消费方且其调度语义一致，届时再单列提案；语义不同则各自实现、不复用。工具失败转为结构化异常并进 gaps，不中断构造。依据：proposal「主要提供」4、spec「执行器调度与异常报告」。
7. **证据传递单向、合成阶段不产生证据**：证据定位随信息数据项从工具输出一路传递到事实，事实合成只组合已有证据，不新增、不伪造、不直接读源码生成证据。依据：proposal「主要提供」6、spec「事实合成与证据传递」。
8. **冷启动可运行、能力渐进成长**：矩阵为空、零解析器时构造器仍可运行——完成契约校验与合成分析、产出信息需求清单，可构造事实为空、gaps 全量显式；随矩阵播种与解析器落地，可构造范围渐进扩大。依据：proposal「核心设计原则」3。
9. **编排粒度：按信息需求聚合、按生产者批量执行**：合成分析产出的信息需求集合（去重，proposal「主要提供」2）经能力矩阵展开为"信息需求 × 生产者"可用对，按生产者聚合后**每工具仅执行一次**；解析产出的信息数据项按信息需求路由给多个事实合成，不重复采集、不重复执行（proposal「主要提供」4）。备选（按事实类型逐个触发工具）被否——同一工具被多个事实共用时重复执行、同一数据项重复进入合成（首轮实现实测：一次查询重复执行 cargo metadata 7 次、同一数据项重复 5 份），违背批量获取语义。依据：proposal「主要提供」2/3/4；能力矩阵行维度=信息需求×生产者（`add-semantic-capability-matrix`）；调研报告（cargo metadata 一次执行覆盖 5 项项目级信息需求）；用户定策 2026-10-23（事实所需信息可由多工具生产、每工具仅调用一次）。验证方式：pytest 以工具执行计数断言同一轮构造内每工具恰执行一次、数据项路由服务多个事实（tasks 4.3）。

10. **生产阶梯为“确定性 / 归纳”二分，不机械按“工具 → Skill → AI”三级**：依据覆盖矩阵结论（报告第 92/101/104 行——数据流、行为约定、模块职责判“不可完成（工具直出）→ 智能体兜底”；第 122 行——工具直出层无不可满足的信息需求、全部弱覆盖项集中在语义归纳类，结论为“解析器聚焦结构抽取、归纳走智能体”）。分层：(a) **确定性层**——工具直出（含产出结构化数据的宿主/外部工具与 Skill，经解析器转信息数据项）；(b) **归纳层**——智能体 / 项目分析 Skill（矩阵 A-*），承担无确定算法的语义归纳。产出结构化数据的 Skill 视同确定性层；只出文本的 Skill 视同归纳层输入材料，不构成独立阶梯。凡矩阵判定存在工具直出生产者（判定非“不可完成”）的信息需求，构造器 MUST 优先走工具直出、MUST NOT 旁路工具直出改由归纳兜底——归纳仅在该信息需求确无工具直出生产者时触发。备选（沿用“工具直出 → 项目分析 Skill → 智能体兜底”三级阶梯）被否——三级只是载体差异、非确定性边界，且“AI 兜底”对归纳类事实是唯一生产者而非末位手段。依据：proposal「核心设计原则」1、「主要提供」3。
11. **兜底交互契约（归纳请求 / 归纳并入）**：构造器对“无工具直出数据项、仅有归纳层生产者”的缺失事实类型，不自行归纳，而以结构化归纳请求随输出暴露，归纳结果经归纳并入接口按契约回传。
- **请求结构** `{type, fields, guidance}`——type 为事实类型、fields 为 fact-catalog 字段清单、guidance 为信息需求清单的 required_info；
- **触发**：仅当事实类型在工具直出合成后仍缺失、且矩阵中存在已点亮的归纳层生产者（A-*，判定非“不可完成”）；
- **并入**：`inducer` 为 `callable(requests) -> {事实类型: [实体]}`，构造器只并入目录内（fact-catalog）且被请求的类型，其余 MUST 拒收（不编造）；
- **证据绑定**：归纳事实的证据由归纳方提供（可回链 file:line），无证据不回填；
- **透传**：未被归纳覆盖的请求随输出暴露，编排层（orchestrator）透传至最终响应；
- **缺口语义区分**：有归纳请求的缺失类型标“待归纳”，无归纳层生产者的缺失类型标“构造后仍缺失”，与工具失败 gap 并存、语义分层。
备选（构造器直接调度归纳类生产者执行）被否——构造器只产出请求并接收并入，归纳由运行本 Skill 的代理承担、经 `inducer` 参数传入。依据：proposal「主要提供」8、「职责边界」。

## Risks / Trade-offs

- [信息需求清单内容的完整性依赖 fact-catalog 字段的封闭性] → 清单编制以 fact-catalog 为封闭边界逐字段派生；发现事实类型字段无法映射到任何信息需求时记入清单的差距段，不静默丢弃。
- [构造器依赖机读契约 schema，而契约现文尚无 schema] → 本变更首个交付物为契约的机读转写（JSON Schema），忠实转写 contract-format/output-schema 现文，不新增结构；与 SFRS 变更的 schema 任务同源、可复用。
- [能力矩阵与解析器尚未落地，构造器长期无信息能力] → 冷启动形态（决策 8）保证编排与清单交付不受阻塞；可构造能力与矩阵/解析器进度解耦，用 gaps 显式表达。
- [归纳层产物质量与确定性边界] → 归纳事实 MUST 附可回链证据 + 契约校验 + 按事实类型验证；MUST NOT 把归纳事实与确定性事实混同标注——缺口语义区分“待归纳”与“构造后仍缺失”（见决策 11）。
- [信息契约（项目信息数据项）字段结构无调研支撑] → 不入正文，列为 Open Question；构造器事实合成只依赖“信息数据项自带证据定位”这一最小接口，字段细化待调研后固化。

## Migration Plan

纯新增：构造器及其测试均为新增文件，不改既有 Skill、契约或 SFRS 文件；回滚 = 删除新增文件，无数据迁移。信息需求清单为本变更的落盘交付物，其落盘路径与形态在 Open Questions 回填后于实现前确定。

## Open Questions

（以下均为无既有调研支撑的结构性决策，按 config design 规则不写入正文，待生产能力调研或设计阶段回填；回填后逐项引用调研纪要来源。）

1. **信息需求清单的内容与粒度**：事实类型字段到信息需求的分解粒度（清单条目结构）。红线：以 fact-catalog 为封闭边界逐字段派生；清单条目结构为设计阶段产出，内容不依赖生产能力调研（调研以清单为输入）。
2. **信息契约的结构与字段**：项目信息数据项 schema 的字段集合（信息类型、内容、证据定位、来源工具标注）。待生产能力调研确认各工具可产出信息的形态后固化机读 schema（JSON Schema，语言无关权威）。
3. **工具链映射配置形态**：矩阵条目中“调用剖面”（命令/超时/重试/输出类型→解析器映射）的字段结构与存储形态，随能力矩阵变更的 schema 定稿后回填。
4. **解析器注册接口协议**：构造器发现并调用外部解析器的统一接口（注册方式、调用约定、错误返回）。属 `add-info-parser` 的设计产出，构造器实现阶段以最小桩接口占位。
