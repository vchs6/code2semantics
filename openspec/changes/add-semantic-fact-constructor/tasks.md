# Tasks

> 阶段顺序遵循配置驱动：本变更首个交付物为契约机读 schema 与信息需求清单（确定性产出），随后实现编排核心、执行器与事实合成。信息需求清单是 `survey-info-acquisition-tools` 的封闭输入——清单落盘前不得以猜测推进调研（见 config rules 与 AGENTS.md 规则 5）。

## 1. 契约机读 schema

- [x] 1.1 忠实转写 query 契约与 output-schema 现文为 JSON Schema（含最小化、gaps 与 out_of_scope 分列、evidence 文件:行号范围），不新增现文外的结构。验证：对照 contract-format/output-schema 逐节核对，schema 文件落盘且通过 JSON Schema 校验
- [x] 1.2 编写契约校验程序（以 1.1 schema 为唯一依据），拒绝目录外事实类型与不合规结构。验证：pytest 覆盖 spec「按契约构造语义事实集」的两个 scenario

## 2. 合成分析与信息需求清单

- [x] 2.1 实现合成分析程序：以 fact-catalog 为封闭边界逐字段派生“事实类型 → 信息需求”的分解。验证：同一契约两次运行产出相同清单（pytest）
- [x] 2.2 产出信息需求清单文件并落盘，覆盖 fact-catalog 全部事实类型字段；无法映射的字段记入清单差距段。验证：清单文件存在，fact-catalog 每类事实均有对应信息需求条目或差距说明
- [x] 2.3 声明清单为确定性交付物并接入构造入口，输出其作为后续调研的封闭输入。验证：构造入口运行后清单可从输出中取回，内容与 2.2 一致

## 3. 执行器

- [x] 3.1 实现执行器：进程生命周期管理、超时、输出捕获与完整性校验，按矩阵条目调用剖面驱动。验证：pytest 覆盖正常退出、超时、空输出三种情形，分别产生输出/结构化异常
- [x] 3.2 实现结构化异常记录与 gaps 归并：工具失败不中断，对应信息需求进 gaps 并标注原因。验证：pytest 覆盖 spec「执行器调度与异常报告」scenario

## 4. 编排核心与生产者选择

- [x] 4.1 实现查矩阵选生产者：依信息需求只读查询能力矩阵，取“判定可完成且解析器已实现”条目；矩阵外无生产者则进 gaps。验证：pytest 以矩阵桩覆盖 spec「按能力矩阵选择生产者」scenario
- [x] 4.2 实现解析器注册接口占位与调用：经统一接口调用外部解析器取信息数据项，解析器缺失进 gaps。验证：pytest 以解析器桩覆盖 spec「输出解析经外部解析器」scenario
- [x] 4.3 实现编排批量获取：同一轮构造内按生产者聚合信息需求，同一工具仅执行一次，其信息数据项按信息需求路由服务多个事实类型且内容不重复。验证：pytest 以工具执行计数断言同一轮内执行次数=1，且多个事实类型由同一次执行的数据项合成（多事实共用单工具的矩阵桩）

## 5. 事实合成与缺口表达

- [x] 5.1 实现事实合成：由信息数据项合成语义事实，证据自数据项传递、不新增不伪造。验证：pytest 覆盖 spec「事实合成与证据传递」scenario
- [x] 5.2 实现输出组装：按 output-schema 组装事实集，gaps 与 out_of_scope 分列、最小化裁剪。验证：pytest 覆盖 spec「按契约构造」「缺口显式与不编造」scenario

## 6. 集成验证

- [x] 6.1 端到端串联：给定契约 + 矩阵桩 + 解析器桩，跑通完整流水线产出符合 output-schema 的事实集。验证：端到端测试通过，输出可被 output-schema 校验

## 7. 代理归纳生产路径（准入：proposal「主要提供」8 / design 决策 11 / spec「语义归纳的请求与并入」定稿）

- [x] 7.1 归纳请求产出：构造器对工具直出合成后仍缺失、且矩阵存在已点亮 A-* 生产者（判定非“不可完成”）的事实类型，产出结构化归纳请求（type/fields/guidance）。验证：pytest 覆盖 spec「语义归纳的请求与并入」——归纳类事实产出请求，含事实类型、fact-catalog 字段与 required_info
- [x] 7.2 归纳并入接口：inducer 钩子按契约回传归纳结果，构造器只并入目录内且被请求的类型，目录外 MUST 拒收，证据绑定（无证据不回填）。验证：pytest 覆盖 spec「归纳结果经契约校验后并入」场景
- [x] 7.3 缺口语义区分：有归纳请求的缺失类型标“待归纳”，无归纳层生产者的标“构造后仍缺失”，与工具失败 gap 并存、语义分层。验证：pytest 覆盖 spec「未覆盖请求保持显式」场景
- [x] 7.4 编排器透传：编排层（适配器 + orchestrator）把构造器产出的归纳请求透传至最终响应，未被归纳覆盖的请求随输出暴露，代理可按请求归纳并经 inducer 并入。验证：端到端测试——查询仅归纳类事实（如配置项）时响应含 induction_requests，代理归纳后并入事实集
