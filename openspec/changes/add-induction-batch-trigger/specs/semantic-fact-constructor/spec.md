# Spec Delta

## MODIFIED Requirements

### Requirement: 语义归纳的请求与并入
构造器 SHALL 对未满足需求产出受约束归纳请求，包括缺少事实、unknown、证据不足及非空但不满足请求，不自行即兴归纳。请求 SHALL 按事实类型、主体、当前来源内容状态和上下文分组，同组字段整组下发、返回及校验，不逐字段拆分，不跨组回填。已有充分证据可归纳，不要求认知能力先由解析器点亮。返回 SHALL 校验请求绑定、字段归属、证据与状态，仅并入目录内且被请求的合规结果；冲突不静默覆盖，未满足项保持 gap。此批组机制承接构造器母能力，不重复实现工具执行或事实合成。

#### Scenario: 整类型缺失产出结构化请求
- **WHEN** 某主体所需事实整体缺失且有可供归纳的证据
- **THEN** 以该事实类型、主体、当前来源内容状态及上下文产出整组请求，列出未满足字段及依据

#### Scenario: 混合形态的空缺归纳字段触发归纳
- **WHEN** 工具已提供部分字段而同组仍有未满足归纳字段
- **THEN** 将未满足字段作为同组整体请求，不因类型已有产出跳过，不要求认知路径先被解析器点亮

#### Scenario: 非空与未知也按需求判断
- **WHEN** 某字段为 unknown、证据不足或虽非空仍不满足请求
- **THEN** 该字段进入未满足集合，与同组其他字段一并交接，而不是只盘点 null

#### Scenario: 待取值集合整组下发不逐字段拆分
- **WHEN** 同一分组含多个未满足字段
- **THEN** 一条整组归纳请求承载这些字段，不逐字段形成重复请求

#### Scenario: 不同主体与来源上下文隔离
- **WHEN** 相同事实类型分属不同主体、当前来源内容状态或上下文
- **THEN** 生成不同组，结果只并入其绑定组，不把一个主体结果填给另一个主体

#### Scenario: 归纳结果经契约校验后并入
- **WHEN** 归纳方返回一组事实
- **THEN** 整组校验请求绑定、字段归属、证据与状态，不合规及目录外事实拒收，不能跨组填入

#### Scenario: 整组结果并入绑定主体的未满足项
- **WHEN** 整组返回中部分字段满足原请求
- **THEN** 将合规结果并入绑定主体，只移除已满足项对应 gap，其余未满足字段保留原因

#### Scenario: 返回冲突不覆盖
- **WHEN** 返回结果与既有有效事实冲突
- **THEN** 保留事实和冲突信息，不静默覆盖，不将冲突当作满足全部需求

#### Scenario: 未覆盖请求保持显式
- **WHEN** 整组归纳未返回或返回仍不满足部分字段
- **THEN** 未满足字段和请求继续以 gap 显式暴露，不编造或占位
