# Proposal

## Why

按事实类型是否存在或字段是否为 null 判断归纳，会漏掉混合事实中已有值但证据不足、unknown 或仍不满足请求的需求。需要在构造器母需求基础上，以同一语义上下文的一组未满足字段为单位触发、校验及并入，避免重复请求和跨主体误回填。

## What Changes

- 细化 `add-semantic-fact-constructor` 的“语义归纳的请求与并入”：盘点未满足需求，包括事实缺少、unknown、证据不足及非空但不满足请求，不以 null 或整类型存在作为唯一判断。
- 以事实类型、主体、当前来源内容状态和上下文共同分组；同组待满足字段整组下发、整组返回与校验，不逐字段拆成独立请求，不把不同主体、来源状态或上下文混入同组回填。
- 已有证据足以支持归纳时即可走受约束认知路径，不要求认知能力必须先由工具解析器点亮。信息不足时仍显式说明缺口，不凭空归纳。
- 并入前校验请求绑定、字段归属、证据与知识状态；只接受公共契约允许的目录内请求事实。非空值不足时可补充满足请求的结果，但冲突必须保留并显式表达，不能静默覆盖既有有效事实；只移除真正已满足项对应 gap。
- 本变更只实现批组触发及并入机制，不重复实现构造器的工具执行、信息分解或全量合成。具体请求和结果结构消费主变更公共契约，不自行冻结旧字段结构或声明旧 schema 无需更新。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `semantic-fact-constructor`：以构造器子变更新增母能力为上游，细化“语义归纳的请求与并入”的未满足需求分组、整组返回、请求绑定和冲突保护；该能力尚未发布，不声称已有实现。

## Impact

- 最新公共契约直接替换旧协议并统一消费者；不保留兼容入口、双轨协议或回退适配，不要求旧数据迁移工具或历史可读承诺。本轮仍只改规划文档。

- 依赖构造器母需求先定稿，再派生本批组机制；实现位置由后续设计和 Skill 包装确定，不引用不存在的旧 constructor.py 或字段映射常量。
- 主变更拥有公共契约；本轮不修改 assets/schema、references、历史验证记录或程序，不创建缺失 design/tasks。
- 后续验证须覆盖整类型缺失、混合字段、非空未满足、unknown、证据不足、多主体隔离、来源状态隔离、冲突与未覆盖 gap；不能以旧 schema 校验通过替代新行为交付。
