# Proposal（软件项目语义事实仓库存储服务，SFRS）

## Why

软件项目的语义事实具有多层次、多类型、相互关联及随项目演进持续变化的特点。需要一个独立、语言无关的存储服务，统一管理软件项目的语义事实，支持按需存储、增量更新、历史追溯和结构化查询，避免语义事实与其生产及使用过程耦合。

## What Changes

新增**软件项目语义事实仓库存储服务**（Semantic Fact Repository Service，SFRS）：一个独立的、语言无关的、支持增量更新的结构化语义事实存储服务。

### 核心定位

**事实由 Skill 产生，仓库负责保存语义事实集、管理事实版本与关系，并提供精确、可追溯、一致的读写服务**。SFRS 的服务对象唯一且确定：`layered-semantic-facts` Skill——Skill 以语义事实集为单位提交提取结果并按需取回已存事实（替代重复提取、渲染报告），除此之外不存在其它客户；数据模型仍保持语言无关，未来向其它消费方扩展不在本提案承诺范围内。

### 主要提供

1. **事实存储**：接收符合输出契约（output-schema 结构化要求）的语义事实集并持久化——进入仓库的是语义事实集，不接收语义报告或人读文档；仓库内部以语义实体、属性与关系为单位组织存储（物理组织为设计阶段产出）。
2. **增量维护**：支持事实的独立写入、更新、失效及批量操作。
3. **版本管理**：支持事实历史与项目版本。项目版本由调用方提交事实时给定（即被分析项目的时点状态），仓库不创建、不推进版本；事实按（项目、版本）持久化，同一事实在相邻项目版本间的状态差异即其历史；按项目版本读取即得到该版本已生效事实的一致视图（不设独立的快照机制与固化操作）。
4. **事实查询**：支持按项目、实体、事实类型及关系进行精确查询。
5. **数据可靠性**：保证存储完整性、事务一致性及事实可追溯性。
6. **统一接口**：为 Skill 提供标准化的事实存储与访问服务；输入与输出均为语义事实集，其结构 MUST 符合主提案响应契约（output-schema）的结构化要求——提交的与查询返回的语义事实集结构一致，均可按 output-schema 校验。实现形态遵循契约消费约定：以契约为指导，先固化契约机读 schema（JSON Schema，语言无关权威），再实现数据结构与处理流程；当前选择为 Python 程序 + SQLite 存储的常规实现（确定性软件，非代理按文档执行），仅为当前选择，不构成对数据模型语言无关性的限定。

### 职责边界

属于存储服务：项目与版本管理（版本读取即一致视图）；语义实体、属性与关系持久化；事实数据结构校验；增量写入与幂等处理；事实版本与历史管理；事实来源与证据记录（来源为对项目源码提交时点的标注，仓库不存储项目源码本身）；结构化查询与关系遍历；索引、事务与数据完整性管理；数据导入、导出和备份。

存储服务的职责以上述清单为限，未列入者均不属于存储服务。特别强调：存储服务可以检查事实是否符合 Schema、引用是否有效、版本是否冲突，但不能自行判断事实所描述的软件行为是否正确。

### 核心设计原则

1. **语言无关**：底层数据模型不包含任何语言专属的硬编码结构。
2. **结构化存储**：语义事实集在仓库内部按具有稳定标识的语义实体、属性与关系组织——接口上以语义事实集为出入单位，存储上分解为实体粒度以支撑增量维护与按范围查询；不把事实集当作一份不可查询单取的整块文档保存。
3. **事实不变、视图可变**：已入库的事实不可直接修改；事实随项目版本演进，其在项目版本序列中的状态变化即其历史；项目当前可见事实由项目版本确定。
4. **增量维护**：仅写入发生变化的事实，避免每次更新都重建整个项目的语义数据。
5. **按范围精确查询**：支持按项目、版本、实体、事实类型、关系等条件查询，不强迫调用方读取完整语义模型。
6. **存储与语义解释分离**：仓库只管理已有事实及其显式关系，不隐式推导新事实。

### 结构决策归属

查询语义的逻辑分层沿用既有分层语义事实模型（事实集需求清单四层结论与 fact-catalog 词汇）；物理存储组织（以语义实体为单位的存取布局、实体稳定标识机制、快照与一致性保证的界定、服务形态）为设计阶段产出，本提案不预设其实现细节。

## Capabilities

### New Capabilities

- `semantic-fact-repository`：语义事实存储服务——事实存储与结构化校验、增量维护与幂等写入、版本/历史/快照管理、按范围精确查询与关系遍历、数据完整性与可追溯性、统一存储访问接口。

### Modified Capabilities

（无。）

## Impact

- 新增：SFRS 存储服务及其 Skill 专用访问接口；底层数据组织与持久化机制对 Skill 透明。
- 不修改：既有 Skill 与项目源码；SFRS 不依赖特定编程语言、语义分析工具或业务工作流，事实的产生（提取）与使用（渲染报告）由 Skill 负责。
- 影响范围：`layered-semantic-facts` Skill 获得语义事实的持久化存取能力——提取结果入库、按契约取回已存事实，避免跨会话重复提取；无其它调用方，底层数据组织与持久化机制对 Skill 透明。
