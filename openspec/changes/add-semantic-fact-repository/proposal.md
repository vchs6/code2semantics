# Proposal（语义事实仓库）

## Why

查询需要可复用、可追溯、可增量维护的结构化事实存储，以区分当前有效事实与来源变化后的失效数据。仓库组件仍待实施，本变更提供独立持久化与精确访问能力，供唯一 Skill 客户端使用，并与查询编排、构造和最终响应装配分工。

## What Changes

- 以主变更公共事实契约定义的结构化事实、实体、属性、显式关系、证据关联及有效性记录为读写对象，内部可按稳定标识组织以支撑定向维护；不以最终 query response 作为存储 API，不存语义报告，不组装用户最小结果。
- 支持增量写入、更新、失效和删除及其依赖影响记录，不要求全量重建。查询流程负责结合当前来源与需求确定复用和失效范围；仓库按提交原子一致地保存事实、证据、有效性及冲突，不自行判断软件语义正确性或推导新事实。
- **BREAKING**：面向用户给定项目集合的当前内容，不提供历史查询、用户版本/快照协议；不强制不可变全历史版本轴或保存历史整源。内部指纹、有效性及一致性机制由设计决定，不能把 stale 事实作为当前有效结果。
- 校验事实结构、引用规则与冲突，失败整体不生效；相同提交幂等，跨连接重读获得已生效的一致结果。外部依赖可按公共契约保留范围外引用，不把所有不在仓库中的引用一律拒绝；非法悬空内部引用仍应拒收。
- 保留源码、清单、配置、文档与观察等证据的定位、上下文及来源状态，不管理整个来源副本；由查询组件验证当前来源并提交有效性更新。可保留失效记录供内部维护，但不能仅凭旧定位存在就将其作为当前命中。
- 支持按项目集合、主体、事实类型、有效性和显式关系精确取回及有限关系遍历，不强迫读取全模型，不隐式推理。保留多项目、多工作空间、重叠目录与同名对象身份边界。
- 数据模型及机读事实契约语言无关；当前可选择 Python + SQLite 作为确定性实现，不把语言或引擎选择变成公共契约限制。统一访问接口只面向 `layered-semantic-facts` Skill；导入、导出与备份维持同一结构与有效性边界。

## Capabilities

### New Capabilities

- `semantic-fact-repository`：结构化事实、证据及有效性的持久化、校验、增量维护、原子幂等写入、一致重读与精确关系访问。

### Modified Capabilities

无。

## Impact

- 最新公共契约直接替换旧协议并统一消费者；不保留兼容入口、双轨协议或回退适配，不要求旧数据迁移工具或历史可读承诺。本轮仍只改规划文档。

- 本变更实施仓库组件；主变更拥有总设计、公共契约与集成验收，查询组件拥有有效性判定编排和最小响应，构造器拥有事实生产，仓库不承担这些职责。
- 公共事实契约由主设计更新，现有 assets/references 仍含旧协议，不以旧 output-schema 校验作为新存储接口已可用的依据。
- 本轮只修订现有 proposal/specs，缺失 design/tasks 待后续派生；不修改产品代码、schema 或历史记录，不归档。
