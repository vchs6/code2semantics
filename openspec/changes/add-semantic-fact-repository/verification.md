# SFRS 实现核对结论（任务 5.2，2026-10-24）

`openspec validate add-semantic-fact-repository` → **valid**。pytest 23 项（schema/model/repository/e2e）全绿。
对照 spec 8 个 Requirement 逐场景核对如下（实现：scripts/sfrs/repository.py + model.py + schema）：

| # | Requirement | 场景 → 核对证据 |
|---|---|---|
| 1 | 语义事实集为读写单位 | 提交取回一致（test_合规事实集提交与取回一致）；语义报告被拒且状态不变（test_语义报告被 rejected）；查询返回可按 schema 校验（sfrs.schema.json 为权威） |
| 2 | 增量维护与幂等写入 | 批量原子生效（submit 单事务，test_不合规被拒状态不变）；单实体更新不影响他者（test_单实体更新）；同内容幂等（test_重复提交幂等 accepted=0）；失效显式操作（invalidate） |
| 3 | 结构校验及其边界 | 结构不符拒绝原因可定位（test_不合规结构，含路径）；引用无效拒绝（test_关系遍历 v2 端缺失）；**不作语义正确性判断**——实现无任何语义逻辑，仅 schema/引用/冲突三类结构校验，按提交内容存储不修改 |
| 4 | 事实不可变与按版本追溯 | 无 UPDATE 路径（事实不可变）；新版本表达新状态、旧版本可追溯取回（test_新版本提交不影响旧版本） |
| 5 | 版本由调用方给定 | 版本为提交入参、仓库不创建不推进；同版本读取确定（幂等测试）；同 ID 不同内容判版本冲突（test_同版本冲突）；无固化操作/快照机制（实现无此概念） |
| 6 | 来源标注与源码不入库 | 仅存 evidence（file/range）时点标注；实现不含任何源码读写路径；源码不可达不影响取回（仓库从不访问源码） |
| 7 | 按范围精确查询与关系遍历 | 按 project/version/fact_type/entity 条件查询只返回匹配（test_精确查询，含未匹配返回空）；遍历只返回显式关系边（test_关系遍历，不推导） |
| 8 | 语言无关统一接口 | 表结构与接口无语言专属硬编码；同接口同校验服务任意语言项目的同构事实集（schema 语言无关词汇） |

**越界检查**：实现中不存在事实语义判断、补全、推导代码；唯三的拒绝路径（schema 不符/引用无效/版本冲突）均为 spec「结构校验及其边界」明示的职责。
