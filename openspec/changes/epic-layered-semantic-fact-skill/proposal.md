# Proposal

## Why

跨语言项目理解与迁移依赖可比较的项目语义信息，但目前缺少一种以统一查询契约获取"最小、分层、语言无关"语义事实的标准化入口。现有的语义分析工作面向固定的单语言上游快照，无法按需回答查询契约。需要一个 Skill 把"按契约取事实"变成可复用、可机器消费的能力。

## What Changes

- 新增一个跨代理环境通用的 Skill（名：`layered-semantic-facts`，可运行于 Codex、CodeArts、Claude、Qoder 等具备代码探索能力的 AI 代理；当前开发宿主为 AtomCode），提供两种工作模式：
  - **契约查询模式**：以给定的查询契约（query contract）为输入，构造并返回符合契约要求、机器可读（JSON）的最小分层语言无关语义事实集。
  - **对话派生模式**：从用户的自然语言对话中提取查询契约（若契约未包含项目存储位置，缺省为宿主当前工作目录），按契约查询模式工作，最终返回人可读的语义事实报告。
- 语义事实集采用分层结构；**具体层级不预设**，由语义事实集调研报告（`survey-semantic-fact-requirements`）经分析与汇总确定，并在 fact-catalog 设计中固化。事实均为语言无关描述并附源码证据定位。
- 输出强调"最小"：仅返回契约所要求的事实层与字段，未要求的信息不得携带。
- 可提供事实目录（fact catalog）：Skill 附带一份预定义、分层的可提供语义事实目录（含语义词汇与字段），作为消费方可查询事实的封闭边界；契约只能引用目录内事实，不能引用目录外事实。
- 职责边界：Skill 的职责是语义事实的提取与呈现，交付上述两种输出；事实的下游工作流（迁移规划、目标语言映射、代码生成等）不在本 Skill 的职责范围内。

## Capabilities

### New Capabilities

- `semantic-fact-query`: 契约查询模式——给定查询契约与项目位置，返回符合契约的机器可读最小分层语言无关语义事实集（含契约校验、分层提取、最小化裁剪、证据绑定）。
- `query-contract-derivation`: 对话派生模式——从用户对话中提取/补全查询契约（项目位置缺省为宿主当前工作目录），驱动契约查询模式并生成人可读的语义事实报告。

### Modified Capabilities

（无——项目尚无既有规范。）

## Impact

- 新增文件：`skills/layered-semantic-facts/SKILL.md` 及其附属参考文件（可提供事实目录、契约格式说明、报告模板）——成果作为本仓库产物随 git 提交。
- 本地测试接入按当前开发宿主的技能安装机制执行（AtomCode：符号链接到 `.atomcode/skills/`，不提交链接目标内容；其他代理环境用各自的技能目录/安装方式，Skill 本体不变）。
- 不修改既有 Skill 与任何项目源码；无新外部依赖，仅依赖宿主已有的代码探索工具（read/grep/glob/list_symbols 等）。
- 影响范围：各代理环境的技能加载目录（Skill 为跨环境通用制品，不绑定单一代理）；对消费方（人或下游工具）提供两种稳定输出格式（机器可读 JSON 事实集、人可读 Markdown 报告）与一份前置确定的可提供事实目录。
