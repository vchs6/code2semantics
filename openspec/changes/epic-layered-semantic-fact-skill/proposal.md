# Proposal

## Why

跨语言软件理解需要一个按查询契约获取最小、分层、语言无关语义事实的统一入口，能够在包含多个独立项目、多个工作空间以及嵌套或重叠软件单元的分析范围内，逐步理解软件的组织、依赖、行为和内部算法。

本变更构建跨代理环境通用的 `layered-semantic-facts` Skill。以[语义事实集需求调研](../survey-semantic-fact-requirements/proposal.md)的验收要求及其[研究报告](../survey-semantic-fact-requirements/research/semantic-fact-requirements.md)为依据，将需求与分层结论依次落实为事实目录、查询契约、响应契约和可验证的生产与查询能力。

## What Changes

- **单一 Skill 与两种模式**：提供跨代理环境通用的统一入口。
  - **契约查询模式**：接受结构化查询契约，交付机器可读的最小语义事实集。
  - **对话派生模式**：从自然语言形成同一查询契约；分析位置缺省为宿主当前工作目录并明确标注，意图不足时先澄清。仅在用户明确要求人可读报告时，由宿主依据同一事实集及报告模板呈现。
- **分析范围与主体身份**：给定目录集合确定观察范围，分别表达工作空间、项目及内部软件单元的身份、边界和来源，覆盖多独立项目、多工作空间、混合目录、嵌套与重叠。身份须有来源命名域及快照依据，同名或相同文件行号不足以判定同一主体；范围本身不自动成为一个项目。
- **从需求派生目录与分层**：采用通过需求覆盖、分层推导、边界论证及场景检查验收的研究报告，先形成 fact-catalog，再依次派生 contract-format 与 output-schema。层数、名称、边界及层间关系由需求分析结论支撑，每项设计可追溯到报告中的问题与事实需求。分析范围与入口、语义粒度、组织关系及贯穿信息的职责依需求确定；查询导航深度不等于软件语义层数。具体字段、节点引用和协议编码由设计确定，支持逐层深入、跳层和多级组成，不强制固定深度或唯一父节点。
- **组织、依赖与交互关系**：区分物理包含、工作空间成员、逻辑从属和内部组成；保留构建、代码接口、运行、数据、部署等依赖与交互的主体、客体、方向、种类、状态、条件及证据。支持多成员、跨项目、跨工作空间、范围外引用和循环。成员关系不代替依赖证据；循环结论须核对联合条件，区分有效环、互斥条件下的候选环和未知情况。范围外引用不扩大源码分析授权。
- **整体语义至内部算法**：覆盖用途、运行形态、架构职责、组件、接口、类型与符号、调用与数据流、状态与资源、错误处理、行为与使用约束，以及代码内部控制流、数据转换和算法意图。表达须保留输入约束、控制与数据更新、边界及错误行为、论证依据与未证实项；语言无关表达保留影响行为的语义差异。
- **证据、知识状态与覆盖**：事实附可复核的源码、清单、配置、文档或观察记录定位及成立上下文，区分直接观察、证据推导和语义解释，显式表达未知、证据不足、不适用、冲突及限定范围内已证实不存在。否定结论须有相应覆盖依据，空值或未发现不足以证明不存在。多个来源分别绑定快照，未提交及未跟踪内容的变化影响当前事实有效性；续查绑定明确事实与快照，历史请求不得静默改绑当前内容。
- **目录封闭与最小查询**：可查询事实类型与字段由目录限定，目录外请求与目录内未满足项分别声明。输出仅含请求节点的直接下一级内容，子树提供可续查引用；同时保留解释结果必需的身份、上下文、证据和覆盖信息。
- **确定性处理与认知归纳**：查询执行读仓库、比较覆盖、按缺口构造、校验入库、重读和最小合成，无进展或达到执行边界时终止并保留缺口。校验、寻址、覆盖、编排、合成与存储由程序执行，语义解释通过带明确主体、字段组、证据、快照和上下文的归纳请求处理。各项事实需求须派生生产信息需求，并按研究及实测证据建立能力矩阵；缺口记录不能代替实际生产能力交付。
- **统一契约与消费者一致性**：目录、契约校验、解析、构造、能力矩阵、覆盖比对、查询合成、事实仓库、调用方及报告呈现同源消费单一契约。契约不匹配的请求或数据须显式识别，不得作为有效命中；事实入库、读取、转换及重建均须维护身份、证据和快照一致性，不得以删除仓库或源项目绕过验证。
- **规范与可验证交付**：Skill 工件遵循 AGENTS.md 引用的 Agent Skills Specification，以 `skills-ref validate` 或规范对照检查表验收。采用真实证据的非空生产、入库、重读和最小查询样例，按研究报告的典型场景验证身份、组织、依赖、内部行为、证据和覆盖；分别报告表达能力、实际生产能力及运行验证结果。

## Capabilities

### New Capabilities

- `semantic-fact-query`：契约驱动的范围与主体查询，交付目录封闭、语言无关、可溯源的最小分层事实集；支持关系表达、节点续查、快照与知识状态、透读构造及显式缺口。
- `query-contract-derivation`：从对话识别并补全同一查询契约，意图不足时澄清；仅在用户要求时指导宿主依据同一事实集生成人可读报告。

### Modified Capabilities

（无。）

## Impact

- **需求与设计输入**：需求调研报告满足其提案验收要求后，依次形成 fact-catalog → contract-format → output-schema；生产信息需求及能力矩阵依据目录开展研究和验证。
- **交付工件与实现**：`skills/layered-semantic-facts/` 包含技能入口、安装说明、参考文档、机读契约、事实目录与矩阵数据，以及解析、构造、查询、覆盖、合成和持久化组件；具体结构、实现选择与依赖由设计依据研究确定。
- **端到端一致性**：各消费者及调用方使用统一契约，验证安装包自包含、契约权威单一、快照隔离、引用稳定、非法输入拒绝和真实非空端到端链路。
- **工作流与验收**：由 OpenSpec 工件指令驱动派生和校验规范、设计及任务，通过 apply 执行；Superpowers 用于设计审查、测试先行、实施和完成前验证。完成判定须有实际交付物和验证证据，归档须经用户确认。
