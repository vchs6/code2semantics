# Proposal

## Why

跨语言软件理解需要一个按查询契约获取最小、分层、语言无关语义事实的统一入口；用户提供的目录可能包含多个独立项目、多个工作空间及嵌套或重叠的软件单元，现有单项目边界和旧事实目录无法完整表达其组织、依赖与内部行为。已完成的[语义事实集需求调研](../survey-semantic-fact-requirements/research/semantic-fact-requirements.md)（2026-10-25）提供了新的需求依据，本变更据此重新设计并升级现有 `layered-semantic-facts` Skill 及其消费者。

## What Changes

- 保留跨代理环境通用的单一 Skill 与两种工作模式：
  - **契约查询模式**：接受结构化查询契约，交付机器可读的最小语义事实集。
  - **对话派生模式**：从自然语言形成同一查询契约；分析位置缺省为宿主当前工作目录，意图不足时先澄清。沿用查询子变更的报告职责约定：仅在用户明确要求人可读报告时，由宿主依据同一事实集及报告模板呈现，不另行提取一份事实。
- **分析范围与主体分离**：给定目录只确定观察范围，不自动成为唯一项目根。事实应区分分析范围、工作空间、项目及内部软件单元的身份、边界与来源，支持多独立项目、多工作空间、混合目录、嵌套及重叠；身份不能仅凭同名或相同文件行号合并。
- **依据调研派生事实目录与分层**：以调研报告 §3—§7 为输入，先形成可提供事实目录，再由目录派生查询与响应契约。具体层级、名称、字段、节点引用及协议编码由后续设计依据报告确定，本提案不预设；分层用于导航与深入，不强制所有主体形成固定层数或唯一父节点的树。
- **独立表达组织、依赖与交互**：区分物理包含、工作空间成员、逻辑从属和内部组成；保留构建、代码接口、运行、数据、部署等依赖与交互的主体、客体、方向、条件及证据。支持多成员、跨项目、跨工作空间、范围外引用和循环；成员关系不能代替依赖证据，互斥条件下的候选环不能冒充有效环。记录范围外引用不授权分析其源码。
- **贯通整体语义与实现算法**：覆盖用途、运行形态、架构职责、组件、接口、类型与符号、调用与数据流、状态与资源、错误处理、行为与使用约束，以及代码内部控制流、数据转换和算法意图；语言无关表达须保留影响行为的语义差异。
- **证据、知识状态与覆盖可追溯**：事实附可复核的源码、清单、配置、文档或观察记录定位及成立上下文，区分直接观察、证据推导和语义解释，显式表达未知、证据不足、不适用、冲突及限定范围内已证实不存在。空值或未发现不能自动证明不存在；多个来源保留各自快照，未提交修改也应影响当前事实有效性。续查须绑定明确的事实及快照，不能静默套用到已变化内容。
- **目录封闭与最小查询**：仅目录内的事实类型与字段可以被查询；目录外请求与目录内未满足项分别声明。输出仅含请求节点的下一级内容，子树以可续查引用表示，不自动展开；同时保留解释结果所必需的身份、上下文、证据和覆盖信息。
- **确定性处理与认知归纳分工**：沿用仓库透读、缺口定向构造、校验入库、重读和无进展终止的既有流程；可确定的校验、寻址、覆盖、合成及存储由程序执行，语义解释通过有明确主体、证据和快照的归纳请求处理。新事实需求应逐项派生生产信息需求并核查能力矩阵，不能将旧目录的生产能力判定直接套用于新目录，也不能以全部返回缺口代替能力交付。
- **BREAKING：直接替换旧契约并统一迁移消费者**。不保留旧查询或响应契约的兼容入口；目录、契约校验、解析与构造、能力矩阵、覆盖比对、查询合成、事实仓库及报告呈现须同源消费重新设计的契约。旧事实不能未经验证成为新契约命中；历史数据的识别、重建与迁移由设计明确，不删除旧库或源项目来完成升级。
- **Skill 规范与可验证交付**：Skill 工件遵循 AGENTS.md 引用的 Agent Skills Specification，以 `skills-ref validate` 或规范对照检查表验收。实施应包含有真实证据的非空生产与查询样例，按调研报告 §8 的典型场景验证身份、组织、依赖、内部行为、证据和覆盖；表达能力、生产能力与实际运行验证分别报告。

## Capabilities

### New Capabilities

- `semantic-fact-query`：契约驱动的范围与主体查询，交付目录封闭、语言无关、可溯源的最小分层事实集；支持关系表达、节点续查、快照与知识状态、透读构造及显式缺口。
- `query-contract-derivation`：从对话识别并补全同一查询契约，意图不足时澄清；仅在用户要求时指导宿主依据同一事实集生成人可读报告。

### Modified Capabilities

（无——当前 `openspec list --specs` 的主规范库存为空；以上能力仍由本变更现有 spec delta 承载，不另建同名能力。）

## Impact

- **设计输入**：消费已成稿的需求调研，后续设计依次固化 fact-catalog → contract-format → output-schema；新信息需求触发相应生产能力研究及矩阵核查，不在此重复执行需求调研。
- **受影响工件与实现**：`skills/layered-semantic-facts/` 中的技能入口、安装说明、参考文档、机读契约、目录与矩阵数据，以及解析、构造、查询、覆盖、合成和持久化组件；具体结构、实现选择与依赖由设计依据研究和现状确定。
- **关联变更**：查询、构造、仓库、解析、能力矩阵及打包变更的契约消费约定需随新上游核对并协调修订；无证据支撑的新生产能力不得点亮。
- **消费者迁移**：这是破坏性升级，需同步迁移调用方及相关测试，验证安装包自包含、契约权威单一、快照隔离与非空端到端链路；不保留旧协议兼容测试作为新契约要求。
- **工作流准入**：由 OpenSpec 工件指令驱动派生和校验下游规范、设计与任务，Superpowers 约束设计审查、测试先行、实施和完成前验证。现有下游工件与旧任务完成标记不代表本次升级已设计或实现完成；需重新派生、验证后再通过 apply 推进。
- **本轮修改边界**：仅修订本提案草案，不在本轮代写下游工件或实施产品；提案经审核后由既定工作流处理后续工作。归档须另行获得用户确认。
