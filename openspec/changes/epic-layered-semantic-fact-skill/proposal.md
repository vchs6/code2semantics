# Proposal

## Why

代码语义分析需要面向用户给定当前项目或项目集合的统一事实查询入口：按明确观察粒度返回最小、可追溯、语言无关的语义事实，并诚实呈现证据、冲突和缺口。已有[事实需求研究报告](../survey-semantic-fact-requirements/research/semantic-fact-requirements.md)已提供四层观察与事实目录依据；本主变更负责把该依据落实为总设计、公共契约、组件依赖编排和集成验收。

## What Changes

- 保留研究报告确定的四层观察、事实目录及组织职责、内部行为、证据和覆盖需求，不重新调研或预设另一套分层。先派生 fact-catalog，再派生查询契约 contract-format，最后派生响应契约 output-schema；结构与字段在设计阶段追溯到报告。
- 保留多独立项目、多工作空间、混合目录、嵌套重叠与同名身份边界；成员关系不能替代依赖证据，跨项目、跨工作空间与范围外关系分别表达。保留联合条件有效环与互斥候选环的区别、来源性质与知识状态正交、限定否定的覆盖依据、目录外与目录内缺口分列，以及最小投影必要的 context、coverage、basis。
- 提供一个 `layered-semantic-facts` Skill，支持结构化契约查询与对话派生同一契约；仅用户明确要求时从同一事实响应生成可读报告。遵循 Agent Skills Specification，以 `skills-ref validate` 或逐项规范检查表验收。
- **BREAKING**：查询限定用户给定的当前项目或项目集合；不提供历史查询、用户快照、revision 或 refresh 协议。来源更新后，在用户查询时结合既有有效事实、变化和本次需求，增量重构受影响请求及必要关联；失效或删除内容不能作为当前命中，不自动全量重构。内部内容指纹可作为实现选择。范围外依赖只保留引用，不扩大源码读取授权。
- 一次查询固定目标与观察粒度，只返回请求节点所需事实及其直接节点的最小字段与必要证据、上下文及缺口，不自动展开后代。请求节点缺少必要上级时，先沿必要上级路径构造；构造任一节点必须完整识别观察边界内直接节点，不能只识别请求匹配部分。未确认完整性必须记录缺口，不能充分命中；识别直接节点不等于递归构造每个 child 的完整事实集。允许多父关系，循环关系不递归组织成树，上级构造结果不全部输出，后续深入以新查询引用。
- 能力矩阵初始为空，仅说明工具可用性与已验收点亮状态，不作为事实生产者或调度者。开发期由构造器子变更设计/任务先交付固定信息需求清单，新增需求通过提案触发工具研究和解析器开发验收；工具研究按该清单增量补充未点亮工具说明，记录信息输出种类、覆盖、限制、平台环境、调用说明和组合方式；一个需求允许多工具组合，先比较覆盖与环境，再偏好轻量、简洁、多语言支持。已有工具研究报告是待按新需求复核的材料。只有解析器开发流程完成才能点亮；研究和构造器均不得点亮，点亮表示工具已通过接入验收、可被构造器使用。
- 解析器只将 `tool-native-output + invocation-profile` 转为统一来源信息，不执行工具、不读取仓库、不选择工具、不构造事实、不维护矩阵。构造器消费请求、既有事实、未满足项和当前来源上下文，只消费开发期已交付的既定信息需求清单，匹配请求与未满足项、聚合为当前获取计划，选择组合已点亮工具并执行，再归纳为事实返回查询流程；不直接持久化，不组装最终响应。运行期不生成或扩展信息需求清单，不触发工具研究、解析器开发或点亮；未覆盖需求返回缺口，待开发期变更处理。
- 归纳按未满足需求触发，包括缺少、unknown、证据不足及非空但不满足需求；按事实类型、主体、当前来源内容状态和上下文分组字段，保留证据、冲突及缺口。仓库存储结构化事实、证据关联及有效性，不以最终 response 作为存储接口。
- 查询流程执行覆盖比对 → 构造 → 校验入库 → 重读 → 最小响应；满足请求、无有效覆盖进展或预算终止时返回已有有效事实与明确缺口。确定性校验、持久化、覆盖比对及编排必须实现为可测试程序，认知归纳保持独立接口。
- 旧契约无需兼容：后续按最新设计统一替换公共定义、样例、接口说明及消费者，不设兼容入口、双轨或旧数据迁移工具；矩阵不另设生产状态，调用运行、超时、重试和成功失败由执行器管理。
- 主变更只拥有总设计、公共契约迁移、依赖编排和集成验收；八个子变更分别实施组件，主任务引用其交付，避免重复实现。现有 `assets/`、`references/` 与验证代码含旧协议，必须作为待迁移资产，不能因文档或既有校验通过就宣称新契约可用。

## Capabilities

### New Capabilities

- `semantic-fact-query`：当前项目集合内按固定观察粒度进行有效覆盖、增量构造、结构化事实入库重读及最小响应，保留关系、证据、完整性和终止缺口。
- `query-contract-derivation`：由对话识别并补全同一当前项目查询契约；按用户明确请求从同一响应生成可读报告。

### Modified Capabilities

无；当前 `openspec/specs/` 未发布既有能力。

## Impact

- 主变更下 `proposal.md`、`specs/`、`design.md`、`tasks.md` 及关联追溯、验收说明形成权威规划。本轮只修订这些现有文档，不实施、不归档，不修改研究报告、schema、验证代码或产品代码。
- 八个组件变更：`survey-info-acquisition-tools`、`add-semantic-capability-matrix`、`add-info-parser`、`add-induction-batch-trigger`、`add-semantic-fact-constructor`、`add-semantic-fact-repository`、`add-semantic-fact-query`、`define-skill-packaging`。其设计、任务和实现不得假定已交付。
- 后续公共契约迁移涉及 `skills/layered-semantic-facts/assets/` 与 `references/`；各子变更按公共契约实施组件，集成验收必须展示真实工具来源、非空事实、持久化重读与需求覆盖，分别记录工具接入验收证据和端到端集成证据，不在矩阵另设生产状态。
