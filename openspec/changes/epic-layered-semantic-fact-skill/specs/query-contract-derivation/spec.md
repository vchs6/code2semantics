# Spec Delta

## Purpose

让使用者从自然语言形成与结构化模式一致的语义事实查询契约，明确观察范围与事实需求，在意图不足时进行澄清，并在明确请求报告时由宿主依据同一事实结果呈现可复核说明。

## ADDED Requirements

### Requirement: 对话派生同一查询契约
Skill SHALL 从自然语言提取观察范围、查询目标与所需事实，形成与契约查询模式相同的查询契约并执行，MUST NOT 建立独立目录、隐藏过滤条件或绕过契约校验。

#### Scenario: 完整意图
- **WHEN** 用户明确请求指定目录集合中项目的运行用途与入口
- **THEN** 形成可检查的同一查询契约，结果遵循目录、投影、快照及证据规则

### Requirement: 观察范围缺省标注
当前查询缺少分析位置时，Skill SHALL 以宿主当前工作目录补全观察范围并标注默认来源；MUST NOT 将目录自动认作唯一项目或工作空间。历史查询 MUST 保持其明确历史范围和快照。

#### Scenario: 当前目录包含多个项目
- **WHEN** 用户未给位置，宿主目录包含多个独立软件单元
- **THEN** 缺省仅限定观察范围，各主体仍按身份与边界证据分别识别

### Requirement: 意图不足先澄清
不足以形成可执行契约时，Skill SHALL 给出目录内事实选项或示例并请求澄清，MUST NOT 自行猜测事实需求而生产结果。

#### Scenario: 模糊请求
- **WHEN** 用户仅说“帮我看看”且上下文不足以确定所需事实
- **THEN** 请求用户明确查询事实，澄清前不执行猜测的事实提取

### Requirement: 明确请求时由宿主呈现报告
两种模式 SHALL 使用同一机器事实结果。仅当用户明确请求人可读报告时，宿主 SHALL 依据同一结果与模板呈现；报告 MUST 保留身份、知识状态、成立条件、覆盖、证据定位和缺口，不补造未请求或未证实事实。报告格式不得反向改变机器契约。

#### Scenario: 默认返回机器结果
- **WHEN** 对话已形成有效查询且未要求报告
- **THEN** 交付机器可读事实，不强制附加 Markdown 报告

#### Scenario: 报告和机器事实一致
- **WHEN** 用户明确请求报告，结果含语义解释、证据不足和限定否定
- **THEN** 宿主保留这些区别并引用可复核的源码、清单、配置、文档或观察依据，不把报告措辞升级为已证明结论
