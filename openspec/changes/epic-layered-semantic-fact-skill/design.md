# Design

## Context

本项目是全新的 Skill 仓库：git 已初始化（main 分支），OpenSpec 已初始化（spec-driven schema）。**Skill 是跨代理环境通用的制品**（可运行于 Codex、CodeArts、Claude、Qoder 等具备代码探索能力的 AI 代理；当前开发宿主为 AtomCode）：成果作为仓库产物开发在 `skills/layered-semantic-facts/`，本地测试时按当前宿主的技能安装机制接入——AtomCode 下符号链接到 `.atomcode/skills/`，其他代理环境用各自的技能目录。宿主提供代码探索工具（read_file、grep、glob、list_symbols、list_directory 等）与子代理委派（task/team），这些是各代理环境的通用能力面，Skill 本体是纯指令文档（SKILL.md + 参考文件），不依赖任何宿主专属 API。

调研依据（config 规则：epic 开始前需先完成语义事实集需求调研）：

- 语义事实集需求清单（`../../survey-semantic-fact-requirements/research/semantic-fact-requirements.md`，下称"事实清单"）：归纳了语言无关语义表达所需事实，经分析汇总给出四层结构（项目/模块/符号/事实）——层级是调研结论，本设计引用而非预设。

## Goals / Non-Goals

**Goals:**

- 单一 Skill（`layered-semantic-facts`）承载两种模式：契约查询模式与对话派生模式；后者复用前者，仅前置于契约提取与报告渲染。
- 定义稳定的输出形态：机器可读 JSON 事实集（分层结构，层级由 fact-catalog 依据事实清单结论定义）与人可读 Markdown 报告，二者内容一致。
- "最小化"作为硬约束：输出仅含契约要求的层与字段；不可满足项进 gaps，不编造。

**Non-Goals:**

- 职责边界以提案为准（proposal「职责边界」）：Skill 的职责是语义事实的提取与呈现，交付机器可读语义事实集与人可读语义事实汇总报告两种输出；事实的下游工作流（迁移规划、目标语言映射、代码生成等）不在本 Skill 的设计与行为范围。
- 不构建独立 CLI 或持久化服务；不修改任何既有技能与项目源码。
- 不追求全语言覆盖——语言无关性由"语义词汇 + 宿主工具抽象"保证，具体语言差异靠逐项目提取时的证据绑定消化。

## Decisions

1. **技能形态：SKILL.md + 附属参考文件，渐进披露**。SKILL.md 只保留模式路由与硬性规则（契约缺省、最小化、gaps 不编造、目录外判超出范围、澄清时机）；fact-catalog、契约格式、输出 schema、报告模板分别放独立参考文件，按需加载。理由：技能内容会被整段注入上下文，拆分显著降低 token 成本。备选（单文件全量内联）被否——每次触发都付出全部内容的成本。
2. **契约格式：结构化 JSON，允许从自然语言派生**。契约至少含 `project`（存储位置）与 `facts`（所需事实的分层与字段描述）；对话派生模式先产出同一结构的契约再执行，两模式共享同一条执行路径。契约可引用集以 fact-catalog 为封闭边界（spec `semantic-fact-query`「可提供事实目录前置确定」）。备选（自由文本契约）被否——无法稳定判定"是否满足契约"。
3. **层级采用事实清单的调研结论**：fact-catalog 的层级依据事实清单分析汇总的四层（项目→模块→符号→事实）固化，本设计不另行创设或改判层级。依据：事实清单"项目层/模块层/符号层/事实层"各节及"语义表达中的作用"论证。
4. **语言无关性：语义词汇表 + 宿主工具抽象层**。可提供事实目录固定一套语言无关语义词汇（模块/入口/配置项/公共接口等，见事实清单各层的语义词汇字段），SKILL.md 指示执行者把各语言的结构映射到这些词汇；证据定位统一为"文件:行号范围"。备选（按语言定义适配器）被否——本项目无多语言基线，适配器把复杂度前置。
5. **执行引擎：宿主现有代码探索工具，可选子代理并行**。提取依赖宿主通用能力面：符号层用 list_symbols/ast_grep/trace_*，模块层用 file_dependencies/blast_radius，项目层用 read_file+主会话归纳；大项目按模块用 `task` 子代理并行，主代理负责契约校验、最小化裁剪与汇总。备选（要求外部解析器如 LSP 独立进程）被否——宿主已内建等价能力，无需新依赖。
6. **封闭世界与缺口语义**：目录外引用判"超出范围"，目录内但项目中缺失的事实进 gaps，二者在输出中分列（spec 场景「目录外引用与 gaps 区分」）。
7. **最小化的实现位置：输出前统一裁剪**。提取可放宽，但输出前按契约逐层逐字段裁剪，保证"最小"是可检验的最终性质而非提取过程的约束。

## Risks / Trade-offs

- [语言无关词汇表覆盖不足] → 词汇表作为参考文件允许随项目演进补录，未覆盖情况记入 gaps 而非强行归类。
- [大项目提取成本高] → 分层渐进提取：先项目层，契约未要求更深则停止；必要时子代理并行分摊。
- [对话意图提取歧义] → 以"澄清时机"规范兜底（spec `query-contract-derivation`「意图不明时的澄清」），宁可多问不猜。
- [报告与 JSON 双产出不一致] → 规范要求报告从事实集生成（单一事实源），不平行提取两遍。
- [跨宿主能力差异] → 提取依赖的能力面（代码探索、符号、调用图）在各代理环境中均有对应物，Skill 执行者按等价能力面映射；映射失败的事实类型进 gaps 并在输出中标注。

## Migration Plan

纯新增：成果开发在仓库 `skills/layered-semantic-facts/` 并随 git 提交；本地测试按当前开发宿主的技能安装机制接入（AtomCode：符号链接到 `.atomcode/skills/`，宿主重新加载技能目录即生效；其他代理环境按各自方式安装同一本体）。回滚 = 删除 `skills/layered-semantic-facts/` 与对应接入链接。无数据迁移。

## Open Questions

- **生产方式声明与弱覆盖事实处理**：每类事实由什么工具/Skill/智能体生产（fact-catalog 生产方式）、数据流/行为约定等弱覆盖事实如何处理（弱绑定标注或缓加入目录）——此类结论需要生产能力调研支撑，本设计无调研依据，不固化；待相关调研完成后回填。
