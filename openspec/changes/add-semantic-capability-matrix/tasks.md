# Tasks

> 阶段顺序遵循配置驱动：schema 先行（唯一校验依据）→ 校验脚本 → 播种/更新脚本 → 查询接口 → 集成验证。播种与更新的真实数据依赖调研报告落盘，验收先用样例 fixture（见 design Risks 与 AGENTS.md 规则 5：交付以落盘为准）。

## 1. 矩阵 schema 与骨架

- [x] 1.1 确定矩阵落盘目录与文件布局（随仓库提交，见 design 决策 3），实现矩阵机读 schema（JSON Schema：条目维度=信息需求×生产者，字段=判定等级/生产层级/运行平台/运行指导/调用剖面/证据引用/状态，含枚举与必选性），并创建空矩阵骨架（占位标识显式标注）。验证：schema 通过 JSON Schema 校验；骨架文件存在且通过 schema 校验
- [x] 1.2 实现一致性校验脚本：证据回链、无孤儿条目、判定与状态自洽，失败给可定位原因。验证：pytest 覆盖 spec「一致性校验」两个 scenario（孤儿条目、证据无法回链均被检出）

## 2. 播种与更新脚本

- [x] 2.1 实现播种脚本：以样例调研报告 fixture 为输入，覆盖矩阵→矩阵条目的忠实转换（判定三档、逐格证据、差距清单）。验证：pytest 覆盖 spec「播种为报告的忠实转换」三个 scenario（同报告两次播种结果一致、增量刷新对应条目、不编造不立项）；校验脚本接入播种出口
- [x] 2.2 实现更新脚本：解析器落地/新工具接入时点亮条目或增补生产者，每次更新版本化保留变更痕迹。验证：pytest 覆盖 spec「更新点亮条目且版本化」两个 scenario；校验脚本接入更新出口
- [x] 2.3 实现"矩阵不自行生产内容"约束：空矩阵且无报告时播种/更新均拒绝生成条目。验证：pytest 覆盖 spec「矩阵只记现状且内容外源」两个 scenario

## 3. 只读查询接口

- [x] 3.1 实现只读查询接口（同进程库调用，见 design 决策 5）：按信息需求/事实类型取生产者链（含生产层级、调用方式、运行平台与运行指导），支持运行平台筛选；无写入路径。验证：pytest 覆盖 spec「只读查询接口」三个 scenario（取生产者链、平台筛选、查询不改矩阵）

## 4. 集成验证

- [x] 4.1 端到端串联：样例报告→播种→一致性校验→解析器登记（fixture）→点亮→查询，产出可供构造器消费的矩阵。验证：端到端脚本一次通过，产出矩阵通过 schema 与一致性校验，查询结果含平台筛选后的生产者链

## Workflow follow-up

- `survey-info-acquisition-tools` 报告落盘后，以真实报告执行一次播种并通过一致性校验（真实数据集成验证）。
- 构造器信息需求清单落盘后，对齐矩阵行维度标识（回填 design Open Question 1）。
- `add-info-parser` 注册接口协议定稿后，回填调用剖面字段结构（design Open Question 3），并以真实解析器登记执行一次更新验证。
- 生产能力调研回填 fact-catalog 生产方式后，固化生产层级词汇表（design Open Question 2）。
