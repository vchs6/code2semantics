# Proposal

## Why

构造器需要查询工具能提供哪些信息、适用环境与点亮可用状态，单靠调研报告无法稳定支持机器查询和状态维护。本变更落实[主变更](../epic-layered-semantic-fact-skill/proposal.md)拥有的公共契约，提供初始为空、由外部依据维护的工具信息能力说明组件。

## What Changes

- 提供矩阵存储、确定性维护与校验程序及只读候选查询；矩阵仅记录普通分析工具与独立项目分析类 Skill 可提供的结构化来源信息、覆盖限制、语言平台环境、调用剖面、组合说明与验收可用状态，不作为事实生产者、调度器或运行时选型者。
- 公共矩阵 schema 及跨组件契约由主变更总设计负责；本变更负责组件落实和契约符合性，不平行定义另一套公共权威，也不预设字段结构。
- 矩阵初始为空。开发期构造器变更在提案、设计与任务中形成或新增信息需求清单后，工具调研根据既有报告增量复核，通过维护接口补充有依据的工具说明；新条目保持未点亮。
- 只有解析器开发完成后的流程，在完成对应原生输出与调用剖面的解析转换可用性验证后，才能经更新接口点亮对应工具。点亮表示该工具已通过开发流程验收、可供构造器调用，不另设生产状态，也不以端到端语义生产、入库或投影验收为点亮前置；研究、新工具接入和构造器不得点亮，运行时解析器不维护矩阵。
- 同一研究依据重播保持结果可重复，未变化条目不得无故撤销已点亮状态；工具输出或解析契约实质变化时，通过开发维护流程撤销点亮并重新开发验收，防止沿用失效的可用性；单次调用失败、超时、重试等临时工作状态由执行器管理，不自动改变点亮状态。
- 只读查询支持按信息需求及语言平台环境取得普通工具和独立项目分析类 Skill 的信息获取候选、覆盖限制、调用与组合说明，允许多工具组合覆盖一个需求。构造器负责比较覆盖与环境后选择组合，轻量、简单、多语言为后续偏好，矩阵不固化全局唯一工具链。
- 差距仅说明当前覆盖与点亮可用状态的不足，不自动立项、不生成事实或执行工具；AI 归纳不作为工具解析能力登记。

- 统一消费主变更最新公共契约，直接替换旧契约资产；不保留旧契约兼容入口、双轨或回退适配。

- 信息需求清单是构造器变更的开发期设计与任务交付；工具研究、解析器开发及验收点亮均在开发期完成。运行时构造器只消费既定清单与已点亮矩阵，不生成开发期需求清单，不启动研究、解析器开发或点亮。

## Capabilities

### New Capabilities

- `semantic-capability-matrix`：工具信息能力说明的存储、受控维护、点亮可用状态及验收证据登记、契约校验与只读候选查询。

### Modified Capabilities

无，当前主规范未归档。

## Impact

- 主变更负责总设计、公共契约和集成验收；本子变更实施矩阵组件。
- 消费工具调研依据与解析器开发流程的验证结果，为构造器提供只读候选说明；不要求重新研究四层事实目录。
- 本轮仅修订已有 proposal/spec，不修改 schema、研究报告或产品文件，不创建 design/tasks，不实施或归档。


## 更新：工具与独立 Skill 同层信息获取能力登记（2026-10-27）

- 能力矩阵是结构化来源项目信息获取能力索引，不登记彼此独立的 F1–F18 事实生产器；普通工具与独立项目分析类 Skill 同层候选，不固化工具优先或 Skill 兜底的严格序列。构造器可以组合选取。
- Skill 候选记录可提供的信息类型、真实输入输出、语言/混合语言覆盖、来源证据、版本与官方安装方法、成本/缓存/更新限制及权限要求。CodeGraph Explorer 仅为已调研但尚未完成生产适配验收候选。
- 候选首次保持未点亮。工具或 Skill 的输出/调用剖面通过开发期解析与信息有效性验收才由受控流程点亮；安装成功与报告描述均不视为点亮依据。矩阵不执行分析、不生成事实、不承担运行时选型。
- 同质量下更低的总获取成本可以成为构造器选择 Skill 的理由，无需证明它拥有普通工具不能提供的独有语义事实。
