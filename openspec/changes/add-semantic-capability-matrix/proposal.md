# Proposal（项目生产能力矩阵）

## Why

构造器要按信息需求选择生产者（工具/Skill/智能体），需要一份**机器可读、可校验、可演进**的能力资产，而非一次性调研报告：报告是证据载体、难以被程序查询与演进追踪；随解析器落地与新工具接入，能力现状持续变化，必须有一份结构化的单一事实源来承载“谁能生产什么、判定等级、调用方式”。这正是构造器只读查询、调研播种、解析器逐格点亮的枢纽。

## What Changes

新增**项目生产能力矩阵**（Capability Matrix）：一份结构化、版本化、机器可读的生产能力资产，以“信息需求 × 生产者”为维度，记录各生产者对信息需求的判定（可完成/部分可完成/不可完成）、生产层级与调用剖面。矩阵由确定性脚本维护，供构造器只读查询。

### 核心定位

**矩阵是生产能力的“现状 as-is”记录，是构造器选择生产者的唯一只读依据。** 矩阵本身不生产自身内容：其内容由生产能力调研的覆盖矩阵报告**播种**（确定性转换），由解析器落地与新工具接入**增量更新**；矩阵只记录现状与差距，不做“要不要建解析器”的立项判断——该判断属于解析器提案自身的门禁。

### 主要提供

1. **矩阵 schema**：定义矩阵条目的结构（信息需求 × 生产者：判定等级、生产层级、调用剖面、运行平台、运行指导、证据引用、状态），为机读权威（JSON Schema，语言无关）。
2. **存储形态**：版本化的结构化存储，支持 diff 评审与演进追踪。
3. **播种脚本**：将生产能力调研报告的覆盖矩阵**忠实转换**为矩阵条目（确定性转换，可重复执行）；报告增量 → 矩阵增量刷新。
4. **更新脚本**：解析器落地或新工具接入时，点亮对应条目、增补生产者；重大变更回溯调研复核。
5. **一致性校验**：校验矩阵内部一致（证据回链、无孤儿条目、判定与状态自洽）。
6. **只读查询接口**：供构造器按信息需求/事实类型取生产者链（含生产层级、调用方式、运行平台与运行指导）；构造器按当前运行平台筛选可用生产者。

### 职责边界

属于矩阵：schema 定义、存储与版本、播种/更新/校验脚本、只读查询接口。

矩阵 MUST NOT：生产自身内容（播种来自调研报告，点亮来自解析器提案）；实现解析器；负责事实构造；决定补建哪些解析器（该决策属解析器提案门禁，矩阵只摆缺口、不代决策）。矩阵中的“未点亮条目/差距清单”是现状缺口，不是待办任务。

### 核心设计原则

1. **现状与决策分离**：矩阵只记录“谁能生产什么”的现状，不承载“要不要建解析器”的立项决策；差距显式摆出，立项由解析器提案按门禁自决。
2. **内容外源、脚本维护**：矩阵内容的唯一来源是调研报告（播种）与解析器落地（更新），播种/更新/校验均为确定性脚本（规则 7），不由代理按文档描述手工维护。
3. **只读消费**：构造器对矩阵只读查询，矩阵不反向依赖构造器；查询接口语言无关，服务不同语言项目的同构信息需求。
4. **可演进**：矩阵随调研增量复评与解析器落地渐进生长，始终作为生产能力的单一事实源。

### 结构决策归属

矩阵条目 schema 的字段结构、存储形态与脚本实现细节，为设计阶段产出（见 design.md）；条目内容由 `survey-info-acquisition-tools` 的报告播种。本提案不预设字段结构细节。

## Capabilities

### New Capabilities

- `semantic-capability-matrix`：项目生产能力矩阵——结构化能力资产：schema 定义、播种/更新/一致性校验脚本、只读查询接口；记录生产者对信息需求的判定与调用方式，供构造器选择生产者。

### Modified Capabilities

（无。）

## Impact

- 新增：能力矩阵组件及其 schema、播种/更新/校验脚本、只读查询接口；矩阵存储。
- 关联但不在本变更修改：构造器（`add-semantic-fact-constructor`，只读矩阵）；生产能力调研（`survey-info-acquisition-tools`，播种来源）；解析器提案（`add-info-parser`，点亮条目）。
- 影响范围：为构造器提供生产者选择的唯一只读依据；为调研覆盖矩阵提供结构化落点；为解析器落地提供能力状态的登记与演进机制。
