# Design（工具生产信息解析器）

## 决策

### 1. 解析为确定性纯转换（规则 7）

每个解析器实现为确定性程序：输入为工具原生输出（含调用剖面声明的输出类型），输出为信息数据项集合或结构化失败结果，无认知决策、无会话状态；相同输入恒得相同输出。实现语言为 Python（与构造器一致，仅为当前选择），验证方式为 pytest 场景覆盖——每个 spec scenario 对应至少一个测试，工具输出以固定样例（fixture）注入，解析行为可判定验证。备选（代理按文档描述即兴解析）被否——不具备"精确、可重复、一致"所需的可确定性。依据：AGENTS.md 原则 7、proposal「核心设计原则」1。

### 2. 契约消费：先固化信息契约机读 schema，再实现解析器数据结构

解析器输出的信息数据项以信息契约机读 schema（JSON Schema，语言无关权威）为校验权威；解析器实现先消费该 schema 生成数据结构绑定（Python），再写转换逻辑，禁止各解析器各自阅读契约文档独立建模。schema 固化前，解析器实现任务不得启动（准入条件见 tasks）。依据：契约消费约定（2026-10-22）、proposal「主要提供」3。

### 3. 框架与实现解耦，注册制增量接入

解析器框架仅承担注册、发现与统一调用约定，不含任何具体工具的转换逻辑；每个工具的解析器为独立实现，按工具标识注册。新增解析器只增不改。框架自身以桩解析器测试（注册→发现→调用→结果回传），不依赖任何真实工具。依据：proposal「核心设计原则」3、spec「解析器可增量接入」。

### 4. 失败为结构化结果，与数据项同型回传

解析失败不是异常中断：解析器以结构化结果表达失败（工具标识、失败原因、不可解析部分清单），与成功的数据项同经统一调用约定回传，由构造器归并进 gaps。依据：spec「解析失败显式表达」、构造器 design 决策 8（gaps 显式）。

### 5. 与构造器的衔接为最小接口

构造器对解析器只经注册接口调用；本变更交付的注册接口协议替换构造器实现阶段的占位桩。解析器不感知调用方——给定输出与输出类型即完成解析，测试不依赖构造器存在。依据：构造器 design「解析器注册接口协议……属 add-info-parser 的设计产出，构造器实现阶段以最小桩接口占位」、proposal「核心设计原则」4。

## Open Questions（待上游产物后回填）

1. **信息契约的字段结构**：信息数据项 schema 的字段集合（信息类型、内容、证据定位、来源工具标注）。待生产能力调研确认各工具可产出信息的形态后固化机读 schema（来源：构造器 design Open Questions 2、`survey-info-acquisition-tools` 报告）。
2. **注册接口协议的具体形态**：注册方式（声明式配置 vs 程序注册）、调用约定的参数与返回结构、错误返回分类。待信息契约 schema 与矩阵条目"调用剖面"字段结构（能力矩阵变更 schema 定稿）确定后固化。
3. **各解析器的覆盖范围与转换规则**：覆盖哪些工具、每工具输出的具体解析规则、覆盖顺序。待信息需求清单与调研覆盖矩阵报告落盘后逐项回填；单个解析器的实现立项以调研复评（短路门禁）通过为前提。
4. **工具输出样例库的来源**：pytest fixture 所需的各工具真实输出样例，随解析器实现逐工具采集固化。
