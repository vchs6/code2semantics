# Proposal

## Why

构造器执行工具后，需要将普通分析工具及独立项目分析类 Skill 的原生输出稳定转换为统一来源信息，保留可追溯证据并明确转换缺口。本变更落实[主变更](../epic-layered-semantic-fact-skill/proposal.md)确定的纯解析组件边界，避免各消费方即兴解析造成契约漂移。

## What Changes

- 提供可注册、发现和调用的结构化信息获取输出的解析器及确定性转换实现，输入为普通工具或独立项目分析类 Skill 的原生结果与调用剖面，输出为符合主变更公共信息契约的统一来源信息项及解析诊断。
- 开发期构造器变更在提案、设计与任务中形成或新增信息需求清单后，按工具调研的环境适用候选与组合说明增量开发或调整解析器；已有[工具调研报告](../survey-info-acquisition-tools/research/semantic-tooling-survey.md)作为按新需求复核的材料。覆盖范围与转换规则以需求、研究依据及公共契约为准，不重新研究四层事实目录。
- 解析器不选择、调度或执行工具，不访问源项目或仓库，不构造事实，不读写矩阵，也不负责持久化或最终响应。调用方提供解析所需输出与调用上下文，解析器不补读来源。
- 来源证据可定位到源码、清单、配置、文档或观察记录等，按来源类型保留可验证回链，不限于文件与行号；不能从输入确定的信息不得编造。
- 无法解析、输出不完整或信息不符合契约时，明确报告范围与原因；部分解析保留可验证且完整的合规信息项，同时报告未解析部分，不输出编造或缺少必需内容的半项。
- 解析器开发完成并通过工具及对应输出与调用剖面的解析转换可用性验收后，由开发流程调用矩阵更新接口点亮对应工具。点亮表示工具已经验收、可供构造器调用，不另设生产状态。该动作不属于运行时解析器职责，且不等待语义生产、入库或投影的端到端验收；输出或解析契约实变时由开发维护流程撤销点亮并重新开发验收；单次调用失败、超时或重试由执行器管理，不自动改变点亮状态。
- AI 认知归纳不伪装为工具解析。构造器可使用已有来源证据进行受约束归纳，解析器未点亮不能成为阻断全部认知需求的统一门禁。

- 统一消费主变更最新公共契约，直接替换旧契约资产；不保留旧契约兼容入口、双轨或回退适配。

- 信息需求清单是构造器变更的开发期设计与任务交付；工具研究、解析器开发及验收点亮均在开发期完成。运行时构造器只消费既定清单与已点亮矩阵，不生成开发期需求清单，不启动研究、解析器开发或点亮。

## Capabilities

### New Capabilities

- `info-parser`：工具解析器的注册发现、纯确定性转换、多来源证据回链、契约符合性及显式部分解析诊断。

### Modified Capabilities

无，当前主规范未归档。

## Impact

- 主变更拥有公共信息契约和跨组件协议，总设计为唯一上游；本子变更负责解析器组件落实及其独立验证，不平行定义公共 schema。
- 构造器负责工具执行与事实归纳，矩阵提供维护接口，开发流程负责经验证后的点亮，运行时解析器与二者保持职责边界。
- 本轮仅修订已有 proposal/spec，不修改 schema、研究报告或产品文件，不创建 design/tasks，不实施或归档。


## 更新：解析 Skill 的结构化项目来源信息（2026-10-27）

- graph.json、局部关系查询 JSON 等 Skill 原生结果与普通工具原生结果平等进入解析接口，按固定信息需求规范化为语言无关的来源信息、证据及诊断；解析器不构造、归纳、持久化语义事实，不要求 Skill 输出 FactBatch。
- 输出须保留来源内容状态/指纹、项目作用域、原始定位、生产者与固定版本、调用剖面、关系的直接提取/解析/推断状态及边界。不因 INFERRED 标记或高置信分数就把候选边当成已证明的语义关系。
- 面对同 mtime 内容变化、无证据或不完整图谱，必须报告新鲜度与转换缺口，不静默输出 current 断言；局部查询按需求投影，不把完整大图不必要地注入模型上下文。
- 候选 Skill 的输出与普通工具相同须有独立转换验收依据，按既有开发期流程维护矩阵；不能把解析通过等同于语义事实构建或端到端验收。
