# Proposal（工具生产信息解析器）

## Why

事实生产流水线中，工具的原生输出（命令行文本、JSON、XML、报表等）与构造器所需的**项目信息数据项**之间存在形态鸿沟：构造器（`add-semantic-fact-constructor`）按设计只调用、不实现解析器，其"输出解析"环节悬空；能力矩阵（`add-semantic-capability-matrix`）的条目点亮也以"解析器已实现"为前提。当前**所有生产工具输出信息的解析部件尚无统一载体**——若各消费方各自即兴解析工具输出，将不具备"精确、可重复、一致"所需的可确定性，且信息契约的落实会在多处漂移。需要把"工具原生输出 → 符合信息契约的项目信息数据项"这一确定性转换固化为独立组件。

## What Changes

新增**工具生产信息解析器**（Info Parser，泛称）：所有生产工具输出信息的解析部件的统一载体，含解析器框架与按工具注册的各解析器实现。

### 核心定位

**解析器是"工具原生输出 + 调用剖面 → 项目信息数据项"的确定性转换组件。** 它是构造器流水线"调用执行 → 输出解析"环节的外部独立组件：构造器经统一注册接口调用解析器，解析器将特定工具的原生输出转换为符合信息契约的项目信息数据项；解析器不调度工具、不合成事实、不感知矩阵与存储。"工具生产信息解析器"为泛称，代指该组件家族——每个已接入的生产工具对应至少一个解析器实现，而非单一工具的专属部件。

### 主要提供

1. **解析器框架**：统一的解析器注册与发现接口（注册方式、调用约定、错误返回——即构造器 design 所留"解析器注册接口协议"的本体），供构造器按矩阵条目的"输出类型 → 解析器映射"调用。
2. **按工具的解析器实现**：各生产工具的原生输出到项目信息数据项的确定性转换；覆盖哪些工具、各解析器的转换规则，以生产能力调研（`survey-info-acquisition-tools`）的覆盖矩阵报告与构造器的信息需求清单为依据，随调研与矩阵演进增量落地。
3. **信息契约落实**：解析器的输出为信息契约（项目信息数据项）——其机读 schema（JSON Schema，语言无关权威）固化后，解析器实现以其为输出权威；每项信息数据项自带源码证据定位（文件:行号范围），证据链自解析器起不可断裂。
4. **解析失败显式**：无法解析、输出不完整或不符信息契约时，以结构化方式报告失败原因，交构造器归并进 gaps；MUST NOT 编造或部分填充。

### 职责边界

属于解析器：解析器注册接口协议；按工具的输出解析实现；输出对信息契约的符合性保证；解析失败的结构化表达。

解析器 MUST NOT：调度或执行工具（执行器属构造器）；合成语义事实（构造器职责）；生产或修改能力矩阵；解读信息需求清单或选择生产者（构造器查矩阵）。语义归纳类信息不经解析器——其生产者按阶梯为分析 Skill / 代理兜底，产出直接为信息数据项，无"工具输出"可解析。

### 核心设计原则

1. **确定性优先**：解析为纯函数式确定性转换（相同输入必得相同输出），实现为程序，MUST NOT 交由代理在运行时按文档描述执行（AGENTS.md 原则 7）。
2. **契约消费约定**：以契约为指导，先固化契约机读 schema（JSON Schema，语言无关权威）——即信息契约 schema——再实现数据结构（Python 绑定等，仅为当前选择），避免各解析器各自阅读文档而漂移。
3. **泛称与注册制**：解析器按工具注册、可增量接入；框架与单个解析器实现解耦，新增工具不改动既有解析器。
4. **纯转换组件**：对矩阵只读（仅在需要时）、对构造器只被调用、对存储零感知；给定工具输出样例，解析行为可独立判定验证。

### 结构决策归属

以下为设计阶段或调研产出，本提案不预设：信息契约的字段结构（待生产能力调研确认工具可产出信息形态后固化，来源 `add-semantic-fact-constructor` design Open Questions 与 `survey-info-acquisition-tools` 报告）；解析器注册接口协议的具体形态（本变更 design 产出）；各解析器的转换规则与覆盖顺序（依据调研覆盖矩阵，实现阶段回填）。

### 立项门禁状态（as-is，2026-10-22）

按既有约定，解析器提案启动前须先经生产能力调研复评（短路门禁：判定无需新工具且解析输出无需变化即止）。当前盘面：信息需求清单未落盘（构造器 0/12）、调研报告 `research/semantic-tooling-survey.md` 未落盘（0/6），复评尚无依据。本提案依用户 2026-10-22 明确指示先行撰写，作为解析器框架与注册协议的**规划工件**；单个解析器的实现立项仍以调研报告与信息需求清单落盘后的复评结论为门禁，tasks 中实现类任务以该门禁为准入条件。

## Capabilities

### New Capabilities

- `info-parser`：工具生产信息解析器——解析器注册与发现接口协议、按工具注册的确定性输出解析实现、输出对信息契约的符合性、解析失败的结构化表达。

### Modified Capabilities

（无。）

## Impact

- 新增：解析器框架与注册接口协议、按工具的解析器实现及其验证；信息契约 schema 固化后的解析器侧落实。
- 关联但不在本变更修改：构造器（`add-semantic-fact-constructor`，只调用解析器，其实现阶段以本变更的注册接口协议替换最小桩）；能力矩阵（`add-semantic-capability-matrix`，解析器落地后由其更新脚本点亮条目）；生产能力调研（`survey-info-acquisition-tools`，解析器覆盖顺序的依据来源）。
- 影响范围：补齐构造器流水线"输出解析"环节的外部组件；随解析器落地，构造器可构造范围与矩阵点亮状态渐进扩大。
