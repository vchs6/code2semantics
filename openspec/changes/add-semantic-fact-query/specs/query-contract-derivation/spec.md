# Spec Delta

## MODIFIED Requirements

### Requirement: 从对话中提取查询契约
Skill SHALL 从自然语言识别当前项目集合、目标、观察粒度和所需事实，形成与结构化查询模式相同的最新公共契约，并沿用同一有效性核对、必要构造、入库重读及最小响应流程。缺省值 SHALL 按公共契约补齐并说明，MUST NOT 另设对话专属版本、快照或旧协议兼容入口。

#### Scenario: 对话给出完整意图
- **WHEN** 用户描述了当前项目及需要了解的事实
- **THEN** 整理为同一契约，执行仓库优先的当前有效事实查询

#### Scenario: 项目位置缺省补全
- **WHEN** 用户未给出项目位置且公共契约允许使用宿主当前目录
- **THEN** 补齐该位置并明确说明缺省

#### Scenario: 仓库位置缺省补全
- **WHEN** 用户未给出仓库位置且可按公共契约补齐
- **THEN** 按确定缺省来源补齐并说明

#### Scenario: 对话指定历史版本
- **WHEN** 用户要求历史项目内容
- **THEN** 明确说明不支持历史查询，不记录旧版本字段或静默回退当前内容

### Requirement: 人可读的语义事实报告
Skill SHALL 交付机器可读最小事实响应；人读报告仅在对话模式且用户明确要求时由宿主按同一事实响应和渲染指令呈现，Skill 不执行渲染。报告 SHALL 按事实目录观察层次组织，保留证据、当前来源上下文、知识状态、冲突及缺口；宿主 MUST NOT 平行提取、补造事实或把未确认完整性写为完整。契约查询模式 MUST NOT 自动产报告。

#### Scenario: 契约查询模式不产报告
- **WHEN** 结构化契约完成查询
- **THEN** 仅交付机器可读响应，不自动生成报告

#### Scenario: 对话派生模式用户未要求报告
- **WHEN** 用户未明确要求可读报告
- **THEN** 交付同一机器可读响应，不强制渲染

#### Scenario: 报告与事实集一致
- **WHEN** 用户明确要求报告且已有查询响应
- **THEN** 宿主只呈现该响应的事实、证据与缺口，不绕过响应另行提取

#### Scenario: 报告保留当前上下文
- **WHEN** 响应中存在冲突、来源变化或完整性缺口
- **THEN** 报告显式保留这些限定，不以历史版本回退叙述掩盖当前缺口

### Requirement: 意图不明时的澄清
对话意图不足以形成可执行契约时，Skill SHALL 澄清项目范围、目标、观察粒度或事实需求，提供事实目录内可选类型及典型示例，MUST NOT 猜测并构造事实。

#### Scenario: 意图不足
- **WHEN** 用户仅表达模糊分析意图而无法确定所需事实
- **THEN** 列出可选需求及示例，请用户明确后再执行相应查询
