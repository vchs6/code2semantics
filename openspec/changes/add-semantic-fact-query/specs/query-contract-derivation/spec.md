# Spec Delta

## MODIFIED Requirements

### Requirement: 从对话中提取查询契约
Skill SHALL 能够从用户的自然语言对话中识别查询意图并形成查询契约。提取的契约 MUST 遵循与契约查询模式相同的契约结构（项目存储位置、事实仓库存储位置、版本与所需事实描述）。对话派生模式 SHALL 沿用同一透读执行流程：优先读取语义事实仓库，仅仓库缺失契约要求的事实时触发事实构造。

#### Scenario: 对话给出完整意图
- **WHEN** 用户在对话中描述想了解的事实（如"这个项目有哪些模块、入口在哪"）
- **THEN** Skill 将其整理为契约并按仓库透读流程执行查询

#### Scenario: 项目位置缺省补全
- **WHEN** 对话中未提及项目存储位置
- **THEN** Skill 以宿主当前工作目录作为项目存储位置填入契约，并在结果中说明该缺省

#### Scenario: 仓库位置缺省补全
- **WHEN** 对话中未提及事实仓库存储位置
- **THEN** Skill 以缺省来源补齐并在结果中说明该缺省

#### Scenario: 对话指定历史版本
- **WHEN** 用户在对话中指定了来源项目的某一历史版本
- **THEN** 契约记录该版本，查询按透读流程的版本语义执行并标注真实版本

### Requirement: 人可读的语义事实报告
Skill SHALL 交付机器可读语义事实集；人可读（Markdown）的语义事实报告仅在**对话派生模式**下且**用户明确要求**时产出——由宿主 AI 代理按给定的语义事实集与渲染依据（`report-template.md` 渲染指令）撰写，Skill 自身不执行渲染；契约查询模式 MUST NOT 产出人可读报告。渲染指令 MUST 约束宿主代理：报告 MUST 与底层机器可读事实集在内容上一致（单一事实源，宿主代理 MUST NOT 绕过事实集平行提取）、MUST 按可提供事实目录定义的层级组织（规范不预设层级）、SHALL 为每条关键事实标注源码证据定位，并 SHALL 标注事实集的真实版本；当真实版本与用户请求版本不一致时，报告 MUST 显式说明该回退。

#### Scenario: 契约查询模式不产报告
- **WHEN** 结构化契约经契约查询模式执行完成
- **THEN** 仅交付机器可读语义事实集，MUST NOT 生成人可读报告

#### Scenario: 对话派生模式用户未要求报告
- **WHEN** 对话派生模式执行完成而用户未明确要求人可读报告
- **THEN** 仅交付机器可读语义事实集，MUST NOT 强制生成报告

#### Scenario: 报告与事实集一致
- **WHEN** 需要人可读呈现，宿主代理按渲染指令、以给定语义事实集为输入撰写报告
- **THEN** 报告所述事实与对应机器可读事实集内容一致，仅呈现形式不同，宿主代理未绕过事实集另行提取

#### Scenario: 报告标注版本回退
- **WHEN** 请求版本在仓库中缺失、查询回退至当前版本完成
- **THEN** 报告显式标注真实版本为当前版本，并说明请求版本在仓库中无信息

### Requirement: 意图不明时的澄清
当对话中的查询意图不足以构成可执行的契约时，Skill SHALL 向用户提出澄清问题，MUST NOT 在意图不明时自行猜测并产出事实集。

#### Scenario: 意图不足
- **WHEN** 用户只表达模糊意图（如"帮我看看这个项目"）而未指明所需事实
- **THEN** Skill 列出可提供事实目录中的可选事实类型与典型契约示例，请用户明确后再执行
