# Design（add-semantic-fact-query）

## Context

- 透读的存储前提由 SFRS 提供（`../../add-semantic-fact-repository/proposal.md`：按（项目、版本）存取、以语义事实集为出入单位、幂等写入、结构校验）；缺口构造由构造器提供（`../../add-semantic-fact-constructor/proposal.md`："契约 + 项目位置 → 符合 output-schema 的事实集"，且"Skill 负责编排构造器并提交事实集入库（SFRS），构造器自身不感知存储"）。
- 既有查询行为定义于 epic 增量规格 `../../epic-layered-semantic-fact-skill/specs/semantic-fact-query/spec.md` 与 `../../epic-layered-semantic-fact-skill/specs/query-contract-derivation/spec.md`（现提模式）；本变更将其重排为透读模式。**2026-10-23 用户裁决（路径 B）**：epic 查询 spec 的最小化语义已修订为「按查询节点下一级返回」——查询以语义事实节点为目标，一次查询仅返回目标节点的下一级节点并标注是否为子树节点，子树内容由消费方续查；本变更按该语义重排透读。
- 契约与输出权威：Skill 参考文件 `contract-format.md`、`output-schema.md`、`fact-catalog.md`（封闭世界规则沿用，fact-catalog 生产方式回填见 epic「待回填项」与本变更 tasks）。

## Goals / Non-Goals

**Goals**：把透读编排循环、覆盖比对、版本判定、降级与不可访问报告按节点粒度落为可运行的确定性程序与更新后的 Skill 参考文件；消除「永远无法构造的字段反复触发构造」的缝隙（构造器声明的缺口为权威）。

**Non-Goals**：不实现构造器内部流水线（归属 `add-semantic-fact-constructor`）；不实现仓库存取（归属 SFRS）；不修改 fact-catalog 的层级与字段定义（仅消费其生产方式回填结果）。

## Decisions

1. **透读编排器实现为 Python 常规程序 + pytest 场景覆盖**（确定性优先，AGENTS.md 原则 7；来源：`openspec/config.yaml` rules.design）。编排器输入为（查询契约、仓库访问句柄、构造器可用性），输出为事实集；循环条件按 specs 的透读编排循环 Requirement 判定。备选"由代理按 SKILL.md 文档即兴执行"被否——编排含状态（已试轮次、上轮入库量），不可重复。与 SFRS、构造器一致的实现形态选择：先固化机读 schema（JSON Schema，语言无关权威）再实现 Python 绑定（来源：项目记忆"契约消费约定"）。
2. **覆盖比对固化为独立可测脚本**（确定性集合运算）：输入（契约定位的节点路径集、仓库返回集，均以 fact-catalog 事实类型与实体标识为词汇），输出（缺口清单，实体级、区分值属性缺失与子树递归分解）；**判缺范围以消费方已请求的节点路径为界**——未被请求的子树节点不参与判缺、不触发构造。验证方式：pytest 表驱动用例覆盖 specs 的"实体级未命中判定"各场景。词汇来源：fact-catalog（本变更只消费不修改）。
3. **契约节点寻址语法**：契约 `facts` 键扩展为节点定位——层与事实类型定位节点，可选节点路径（下一级节点引用列表）指定续查目标；缺省路径即定位该类型节点本身。节点引用形态由返回的"是否子树节点"标注项提供（`{name, is_subtree, evidence?}`）。机读 schema（contract.schema.json）随本决策演进。备选（保持扁平 {层级: [事实类型]} 不变）被否——无法表达续查目标，违背 epic spec 修订后的下一级返回语义。依据：epic 查询 spec「机器可读的最小分层事实集输出（按查询节点下一级返回）」（2026-10-23 用户裁决）。
4. **事实合成器同为独立可测程序**：输入（各轮仓库命中事实 + 构造入库事实的合并集合、契约定位的节点路径、真实版本标识），输出（按已请求节点路径装配的下一级节点集、每个节点带是否子树节点标注、gaps/超出范围分列、版本标注后的最终事实集）。合成是确定性装配（去重、按路径组织、下一级裁剪），实现为程序并以 pytest 覆盖 specs"事实合成按契约结构装配输出"各场景；MUST NOT 由代理在输出时即兴裁剪。
5. **构造器声明缺口为权威（缝隙修法，2026-10-23）**：编排器对构造器的衔接除"契约 + 项目位置 → 事实集"外，还取回其结构化缺口声明（gaps：字段级/节点级原因，如"解析器未实现""矩阵中无可用生产者"）；已声明缺口不再参与后续轮次的判缺与构造触发。备选（查询侧复制构造器信息需求清单的差距段作豁免）被否——同一知识两处维护、清单更新时漂移（会话内已发生同类事故）。依据：spec「透读编排循环」（判缺范围）与「无法满足契约时的显式缺口」（原因区分），用户裁决 2026-10-23。
6. **版本标识**：Git 仓库取当前 commit（`git rev-parse HEAD`）；非 Git 本地文件夹按提案采用内容指纹 + 时间戳作为"始终当前版本"标识，具体指纹算法（哈希范围：全文件还是源码扩展名文件）列为 Open Question Q1。判定来源：本变更 proposal.md"版本语义"（用户确认）。
7. **Skill 参考文件更新范围**：`contract-format.md` 增加"事实仓库存储位置（可缺省）""来源项目版本（可缺省）"与**节点寻址（facts 节点定位与续查路径）**；`output-schema.md` 响应部分增加真实版本标注与**子树节点标注/下一级返回结构**；`SKILL.md` 的执行流程章节改写为透读编排循环（引用编排器程序，按节点粒度描述返回与续查）。contract-format 的机读 schema 演进（JSON Schema 化）遵循契约消费约定，其结构细节依赖既有 `contract-format.md` 当前内容，只增字段不改既有字段语义。
8. **报告渲染职责外移（2026-10-23 用户定策）**：人可读报告仅在对话派生模式下用户明确要求时产出，由宿主 AI 代理按给定语义事实集与 `report-template.md` 渲染指令撰写；Skill 不渲染，契约查询模式不产报告，用户未要求时不强制生成。备选"Skill 自行渲染报告（epic 旧口径）"被否——渲染为认知型呈现任务（AGENTS.md 原则 7 允许代理承担的类别），外移后 Skill 交付物收敛为机器可读事实集，确定性边界更干净；单一事实源约束（不得平行提取）由渲染指令显式固化。

## Risks / Trade-offs

- [最低层节点的首次查询需自顶向下构造整条路径（项目→模块→符号→事实），耗时随来源项目规模增长] → 透读循环一次请求内自动完成，消费方透明；构造产出入库后同版本续查命中仓库，代价仅付一次（2026-10-23 用户澄清：最小化=不扩大范围、不加额外详细事实；父节点缺失先构造父节点）。
- [SFRS 尚未实施，编排器联调缺少真实仓库] → 编排器与覆盖比对针对 SFRS 访问接口编程，测试以接口桩（内存版仓库桩）覆盖全部场景；SFRS 落地后仅替换适配层。
- [构造器产出与仓库判齐规则存在跨变更依赖（直接孩子判齐归属构造器）] → 本变更以"新入库事实数"作黑盒终止判据、以构造器声明缺口作豁免权威，不对构造完整性做白盒假设；跨变更一致性由两提案的 Impact 互引保证。
- [非 Git 项目的"始终当前版本"语义可能造成仓库事实频繁失效重构造] → 指纹相同即命中（Open Question Q1 定算法后固化）；风险限于本地文件夹场景，Git 场景按 commit 精确命中。
- [真实版本回退可能误导下游] → specs 已强制响应标注真实版本；对话报告场景强制显式说明回退。
- [契约寻址语法演进使既有扁平契约失效] → 节点路径为可选字段，既有 {层级: [事实类型]} 契约仍定位节点本身（向后兼容）；schema 校验拒绝的仅是不合规新字段。

## Migration Plan

实施顺序：契约寻址 schema 与覆盖比对脚本（对桩测试）→ 合成器（下一级装配）→ 构造器缺口衔接 → Skill 参考文件更新（contract-format/output-schema/SKILL.md）→ 构造器可用后联通真实链路。回滚：编排器与参考文件改动均可独立回退，回退后 Skill 恢复现提行为（旧流程文本保留于 git 历史）。

## Open Questions

- Q1：非 Git 本地文件夹的版本指纹算法（参与哈希的文件范围、哈希算法选择）——待 design 回填前做有限调研（每事实 ≤2 二手源），不阻塞任务拆分。
- Q2：Skill 调用 SFRS 的进程形态（同进程库调用还是子进程 CLI）——SFRS 提案将"服务形态"列为设计阶段产出，待 SFRS design 定稿后回填本变更适配层形态；不阻塞编排器逻辑开发（对接口桩编程）。
