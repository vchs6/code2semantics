# Proposal（以语义事实仓库为中心的查询流程）

## Why

`layered-semantic-facts` Skill 当前的查询流程是"每次现提"——同一项目在同一版本上的每次查询都重复执行完整提取，且提取依赖代理在会话中按文档即兴执行。`add-semantic-fact-repository`（SFRS）已定稿事实存储与取回、`add-semantic-fact-constructor` 已定稿确定性事实生产组件，查询流程应改为以事实仓库为中心的透读缓存模式：事实从来源项目提取一次入库，此后查询优先命中仓库，仅仓库缺失时才触发源码侧构造，消除重复提取并使查询结果可复用、可追溯。

## What Changes

将 `semantic-fact-query` 的执行流程由"契约 → 现场提取 → 输出"改为"契约 → 仓库透读 → 缺口触发构造 → 输出"：

1. **透读缓存**：查询优先读语义事实仓库（SFRS）；命中即返回，未命中（仓库缺失契约要求的事实）才触发事实构造（构造器，见 `add-semantic-fact-constructor`），构造结果经 Skill 提交 SFRS 入库后作答。每个来源项目版本只提取一次。
   - **透读编排循环**：查询 SHALL 按以下确定性循环编排透读：①按契约读仓库 → ②覆盖比对（契约要求集 vs 仓库返回集，实体级）→ ③差集非空且构造器可用时生成构造任务清单、由构造器构造 → ④构造产出经 Skill 提交 SFRS 入库、入库结果返回循环 → 回到①。循环继续条件为覆盖比对差集非空；终止条件为差集为空，或本轮构造未产生任何新入库事实（MUST NOT 对源码中不存在的事实无限重试）；剩余缺口 SHALL 以 gaps 显式输出。
   - **事实合成收尾**：查询处理的终点 SHALL 是**合成器**——按契约定位的节点路径装配整个透读过程获得的语义事实集（仓库命中事实 + 构造入库事实），执行最小化返回（仅返回已请求节点的下一级节点并标注是否为子树节点，子树内容不返回、由消费方续查）、gaps 与超出范围分列、真实版本标注后输出；MUST NOT 将仓库原始返回直接透传为最终输出。
2. **版本语义**：查询按来源项目版本判定命中——Git 仓库以 commit 标识版本，本地文件夹视为"始终当前版本"。请求版本在库中无信息时，以项目当前版本继续查询（含触发构造），返回事实集 SHALL 标注真实版本，MUST NOT 以当前版本事实冒充请求版本。
3. **未命中粒度**：未命中判定在实体级进行——值属性缺失即该实体为缺口；子树属性缺失不直接记缺口，递归分解为子实体逐个判定。覆盖比对（契约要求集 vs 仓库返回集）为确定性集合运算，固化为程序实现。
4. **构造器为待建依赖**：本变更交付时构造器提案（`add-semantic-fact-constructor`）尚未实施；构造器缺席期间查询 SHALL 降级为只读模式（仓库未命中项直接进 gaps 并标注原因），MUST NOT 退化回现场即兴提取。
5. **不可访问即报告**：来源项目或事实仓库存储位置不可访问时，Skill SHALL 直接报告结果（含原因），MUST NOT 静默降级或改用其它数据源。
6. **对外契约结构调整**：输出仍为符合 output-schema 的语义事实集（含 gaps 与超出范围分列），返回粒度按"查询节点下一级"调整——每个下一级节点标注是否为子树节点，子树内容不随首查返回；输出 schema 随本语义演进（子树节点标注），响应中新增真实版本标注字段；对外不区分事实来自仓库既有还是本次新构造（来源追踪由 SFRS 的证据与来源记录承担）。
7. **仓库位置入契约**：查询契约增加事实仓库存储位置字段（允许经环境变量或固定路径缺省补齐，缺省时在输出标注）。
8. **报告渲染职责外移**：人可读报告仅在**对话派生模式**下且**用户明确要求**时产出——由宿主 AI 代理按给定的语义事实集与渲染指令（`report-template.md`）撰写；Skill 不执行渲染，契约查询模式 MUST NOT 产出人可读报告，用户未要求时 MUST NOT 强制生成。渲染指令 MUST 约束宿主代理以事实集为单一事实源（MUST NOT 平行提取）、标注源码证据定位、显式标注真实版本及版本回退。

### 依赖的上游变更（先核实后引用）

- `add-semantic-fact-repository`（SFRS）：仓库读写、按（项目、版本）存取——已落盘提案，实施状态待其 tasks 推进；
- `add-semantic-fact-constructor`：未命中的缺口构造——已落盘提案，本变更只引用其"契约 → 事实集"接口，不处理其内部实现与"直接孩子判齐"等构造规则（归属该变更）。

## Capabilities

### New Capabilities

（无。）

### Modified Capabilities

- `semantic-fact-query`：查询执行流程由现场提取改为仓库透读；返回粒度按 epic 查询 spec 修订后的语义执行（查询节点下一级返回、子树节点标注、消费方续查）；新增版本语义（版本判定命中、缺失版本回退当前版本并标注真实版本）、实体级覆盖比对（以已请求节点路径为界）、构造器缺席时的只读降级、不可访问报告、仓库位置契约字段。
- `query-contract-derivation`：对话派生模式沿用同一契约结构与同一透读执行流程；契约新增的事实仓库位置与版本字段同样适用于对话派生路径；人可读报告渲染外移给宿主代理（仅对话派生模式下用户明确要求时产出，Skill 不渲染）。

## Impact

- 修改：`layered-semantic-facts` Skill 的执行流程与参考文件（contract-format 增加仓库位置与版本字段；输出响应增加真实版本标注）；Skill 职责表述由"提取与呈现"调整为"契约校验、仓库透读、缺口构造编排与语义事实集交付"（人可读报告仅在对话派生模式下用户明确要求时由宿主代理按给定事实集撰写，Skill 不渲染）。
- 依赖：SFRS（`add-semantic-fact-repository`）提供仓库存取；构造器（`add-semantic-fact-constructor`）提供缺口构造，缺席时降级只读。
- 不修改：SFRS 与构造器各自的职责边界；output-schema 的既有结构与 fact-catalog 内容。
