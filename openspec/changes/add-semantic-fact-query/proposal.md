# Proposal（以语义事实仓库为中心的查询流程）

## Why

当前项目查询需要优先复用有效事实，并在来源变化及请求未满足时定向补构，避免重复分析或把失效事实当作当前结果。本变更负责实施主变更确定的查询编排与最小响应，仓库、构造器及公共契约均有独立归属，尚不能假定已有运行组件。

## What Changes

- **BREAKING**：查询固定用户给定当前项目或项目集合、目标与观察粒度，不支持历史查询、用户 snapshot/revision/refresh；不以 Git commit 代表全部当前内容，非 Git、dirty、untracked 与删除也必须参与来源有效性判断。用户要求历史内容时明确不支持，不静默回退当前内容。
- 以确定性程序执行“读库 → 有效性与覆盖比对 → 必要构造 → 校验入库 → 重读 → 最小响应”。有效事实满足时复用；不足时把请求、有效事实、未满足项及当前来源上下文交构造器，构造器运行期仅匹配开发期既定信息需求清单，清单未覆盖时返回 gap，不在查询中启动工具研究或解析器开发；只有持久化成功并重读后的有效事实进入结果，不将构造输出或仓库原始返回直接透传。
- 结合既有有效事实、来源变化和本次需求增量重构受影响请求及必要关联；修改、删除及依赖影响都要失效或更新，不只 append，不自动全量重建。内部指纹与有效性记录由设计选择，不要求保存历史整源。
- 覆盖判断针对请求语义、知识状态、证据与直接节点完整性，缺事实、unknown、证据不足、非空未满足均可构成缺口；不是仅看实体/字段是否存在。满足请求、无有效覆盖进展或预算用尽时终止；任意无关新事实不能延长循环。有限的本次覆盖集合包含必要上级定位和直接节点完整性义务，满足这些前置义务计入有效进展；识别直接节点不要求其全部事实字段已构造。
- 一次查询不自动后代展开；缺必要上级时先补上级路径，再构造目标。任一构造节点完整识别观察边界内直接节点，未确认完整性必须 gap，不能充分命中；识别 child 不触发递归构造每个 child 的完整事实集。允许多父组织关系，依赖循环与组织关系分离，保证有限调度。
- 最终按主公共响应契约投影请求字段、直接节点及必要身份、证据、context/coverage/basis、完整性与缺口；上级补齐和内部信息不全部返回，子节点可引用供后续新查询深入。目录外请求与目录内未满足分列，范围外依赖保留引用，不扩大读取授权。
- 保留多独立项目、多工作空间、混合目录、嵌套重叠及同名身份边界；成员关系不替代依赖证据，跨项目、跨工作空间与范围外关系依公共契约表达，联合有效环与互斥候选环不得混淆。
- 构造器缺席时只读有效仓库事实并返回明确 gap，不退回即兴抽取；来源或仓库不可访问时报告原因，不换数据源。项目与仓库位置缺省按公共契约补齐并说明，契约字段归主设计更新。
- 对话派生同一契约；意图不足先澄清。可读报告只在对话模式且用户明确要求时由宿主按同一事实响应及渲染指令呈现，保留证据、当前上下文、冲突与缺口，不能平行提取或添加事实。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `semantic-fact-query`：基于主变更新增能力，实施当前来源有效性、有限透读编排、必要构造、入库重读、直接节点完整性及最小响应。
- `query-contract-derivation`：基于主变更新增能力，实施同一当前查询契约的对话派生、澄清及宿主按请求呈现报告。

## Impact

- 最新公共契约直接替换旧协议并统一消费者；不保留兼容入口、双轨协议或回退适配，不要求旧数据迁移工具或历史可读承诺。本轮仍只改规划文档。

- 主变更拥有总设计、公共查询/响应契约与集成验收；本子变更拥有查询组件，消费仓库与构造器接口，不重复实现它们或平行定 schema。
- 当前 Skill assets/references 与验证代码仍含旧协议，公共契约须由主变更后续迁移，本轮不修改、不宣称一致可用。
- 本轮仅修订现有 proposal/specs；design/tasks 缺失保持待后续派生，不实施或归档。后续验收须展示有效覆盖进展、失效更新、真实入库重读与最小响应。
