# Tasks

> 阶段顺序遵循配置驱动与 design Migration：契约寻址 schema 与覆盖比对先行（对桩可测）→ 合成器下一级装配 → 构造器缺口衔接 → 参考文件更新 → 真实链路联通。每阶段以 pytest 场景为验证，实现对既有手写程序按新语义适配。

## 1. 契约节点寻址与覆盖比对

- [x] 1.1 契约节点寻址：contract.schema.json 增节点定位与续查路径字段（层与事实类型定位节点，可选节点路径列表；既有扁平契约向后兼容），contract-format.md 同步说明。验证：pytest 覆盖节点定位契约、续查契约、既有扁平契约三类样例的 schema 校验
- [x] 1.2 覆盖比对适配（design 决策 2）：判缺范围以已请求节点路径为界，值属性缺失/子树递归分解按实体级输出；未被请求的子树节点不参与判缺。验证：pytest 表驱动覆盖 spec「实体级未命中判定」三个 scenario 与"未请求子树不判缺"场景

## 2. 事实合成器（下一级装配）

- [x] 2.1 合成器适配（design 决策 4）：按已请求节点路径装配下一级节点集，每个下一级节点标注是否为子树节点（`is_subtree`），子树内容不出现在输出；gaps 与超出范围分列、真实版本标注保留。验证：pytest 覆盖 spec「事实合成按契约结构装配输出」两个 scenario 与"下一级裁剪"场景
- [x] 2.2 output.schema.json 演进：响应结构增子树节点标注与下一级返回形态（design 决策 7），output-schema.md 同步。验证：合成器输出通过新 schema 校验；既有字段语义不变

## 3. 构造器衔接与缝隙修法

- [x] 3.1 构造器缺口透传（design 决策 5）：编排器经构造器适配层取回结构化缺口声明（节点/字段级原因），已声明缺口不再参与后续轮次判缺与构造触发；编排循环终止判据适配。验证：pytest 覆盖 spec「构造无法补齐时终止」与"已声明缺口不重触发构造"场景（构造器桩返回带原因缺口）
- [x] 3.2 只读降级与不可访问报告适配：构造器缺席时未请求节点进 gaps 并标注原因（沿用既有语义，按节点粒度核对）。验证：pytest 覆盖 spec「构造器缺席时只读降级」「不可访问时直接报告」各 scenario

## 4. 参考文件与真实链路

- [x] 4.1 SKILL.md 执行流程章节改写：透读编排循环按节点粒度描述（请求定位节点 → 下一级返回+子树标注 → 消费方续查），引用编排器程序；contract-format.md 补仓库位置/版本/节点寻址缺省说明。验证：SKILL.md 描述与编排器实际行为一致（对照 pytest 场景清单）；fact-catalog 生产方式回填结果被覆盖比对消费（与 epic「待回填项」回填联动）
- [x] 4.2 端到端联通：内存仓库桩 + 真实构造器适配层，对 indicatif 以节点定位契约查询项目层节点 → 返回下一级（含子树标注）→ 以子树节点续查 → 构造入库 → gaps 精确原因。验证：端到端测试通过，输出通过 output.schema.json 校验，`构建与运行形态` 等含差距段字段的节点不再触发重复构造
