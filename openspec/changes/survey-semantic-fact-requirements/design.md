# Design

## Context

动机与需求以 [proposal.md](proposal.md) 的 Why / What Changes 为准。本变更为中文调研文档，`skip_specs: true`，不引入系统行为或 spec delta。

2026-10-25 已核实 `research/semantic-fact-requirements.md` 存在；2026-10-22 版只讨论项目→模块→符号→事实，缺少当前 proposal 要求的联合分析范围、工作空间及跨单元拓扑。原 tasks 的六项勾选是历史执行记录，不是本次需求已满足的证据。当前用户明确要求重新执行，满足 config 的强制重入条件。

参考边界：旧需求报告提供已有内容的差异基线；[上游获取研究](../../../docs/ref_semantic-fact-survey.md) §3、§3.2 提供工程拓扑与行为遗漏的检查线索；工具研究和存储研究各自描述旧输入的生产/存储决策，不能反向限定本次需求。

## Goals / Non-Goals

**Goals:**

- 使需求、推导和场景验证可追踪：原始需求编号 → 事实条目 → 聚合视图与横向关系 → 场景见证 → 提案一致性检查。
- 每类事实描述语义词汇、必要信息与适用边界；证据状态与覆盖范围独立于内容。
- 本轮一次成稿；有限来源核实后把未决问题登记为差距，不以无限搜索扩大事实集合。

**Non-Goals:**

- 不选定生产工具、智能体、数据库、接口字段编码或输出 schema；不把概念关系表示直接当成物理图存储决策。
- 不在本轮调整下游 Skill 的封闭目录、查询契约或实现；报告登记与旧版的映射和消费风险，由 epic 按 fact-catalog → contract-format → output-schema 顺序处理。
- 不归档本变更。

## Decisions

1. **以原始问题建立封闭需求台账。** 依据 proposal「内部语义与算法」「有界调研与交付」；从消费者需回答的问题列原始需求，逐项派生事实语义，再用文献作佐证。旧需求报告「原始事实需求与外部佐证」提供可比较的起点，但不承继其四层结论。被否备选：按工具输出或沿用旧层级填空，均会遗漏新边界。
2. **分开研究组织、依赖、属性行为及证据。** 依据 proposal「分析范围与软件单元」「组织关系」「依赖与交互关系」「证据与不确定性」；以身份、边界和关系的反例检查约束归纳，保留多成员、跨层、循环、外部引用和未知。已有上游获取研究 §3 的 F01—F03、F23 与 §3.2 支持这些缺口确实需要核查。被否备选：把物理目录和工作空间成员合并为唯一父节点，无法保留独立项目及重叠边界。
3. **聚合粒度在调研后归纳。** 依据 proposal「层级推导方法」；分别汇总聚合对象、对象自身属性与行为、横向关系，再比较候选组织方式。最终名称和数量只在研究报告的推导节形成，design 不提前写入固定层数。被否备选：给旧四层增加一个总根，仍不能解决成员关系、依赖拓扑和行为粒度混杂的问题。
4. **用有界场景见证检查表达充分性。** 依据 proposal「典型场景检验」；为每类场景记录身份与边界、组织、依赖及交互、内部算法、证据及未知的具体见证与反断言。场景是概念表达检验，不声称运行系统已支持。被否备选：仅列场景名称或只做关键词检查，无法发现错误归属和虚假独立性结论。
5. **内容验收与工具校验分离。** 依据 proposal「有界调研与交付」和 AGENTS 原则 5、7、11；认知型研究以需求逐条回溯与场景反证验收；确定性的存在性、编号引用、局部链接、任务完成状态由 Python 3 / OpenSpec CLI 检查，命令与结果记录于 `research/validation.md`，临时检查程序不作为产品代码交付。被否备选：只依赖 OpenSpec validate，其工件校验不能证明研究完整或结论正确。

## Risks / Trade-offs

- [将语言生态规则泛化为普适约束] → 来源只作实例佐证，标明生态适用范围，不把 Cargo 的成员规则强加给编辑器或联合工作空间。
- [负面结论超出证据覆盖] → 无依赖结论必须限定快照、类型、配置和已检查集合；未知与已证实不存在分别记录。
- [旧消费者仍引用四层封闭目录] → 报告列旧版映射及下游差异，调研完成不代表下游兼容或生产能力通过。
- [概念场景被误认作实测] → 明确“推演见证”与“文档核实”，不伪造工具运行、源码样本或性能证据。

## Migration Plan

按 tasks 的本轮重入组通过 apply 交付，保留历史记录。报告替换旧稿，Git 历史保留旧版本。若需撤回可独立回退本轮文档提交；本轮不修改运行代码、下游契约或已归档文件。

## Open Questions

具体契约编码、稳定身份实现、跨版本关联、生产能力和存储方案属于下游设计问题，不阻塞需求调研；在报告的局限与待设计问题节集中交接。本轮方法和交付范围无待决准入项。
