# Design

## Context

本变更是纯调研工件（`skip_specs: true`），不改变任何系统行为。调研对象是**事实需求本身**——软件项目语言无关的语义表达需要哪些事实；生产能力是否可满足不在本变更范围内。结论是 epic `epic-layered-semantic-fact-skill` fact-catalog 的**蓝本输入**：按 config 规则，epic 开始前必须先完成本调研。

调研定位（与下游的边界）：

- **事实需求由语义表达目标决定**，不因现有工具能做什么而改变。
- 产物 `research/semantic-fact-requirements.md` 尚未落盘（research/ 目录为空）；调研重入取决于该报告是否存在或有强制要求——本变更执行时即产出该报告，无强制指示不重跑。

## Goals / Non-Goals

**Goals:**

- 归纳语义表达所需事实：事实类型、语言无关语义词汇、字段描述；**分层结构是本调研的分析产出**——由原始事实经归类汇总得出，层级数量与名称在清单中论证，不预设。
- 每类事实给出语言无关描述，不绑定任何具体语言或工具。
- 清单一次成稿、有界不扩张，作为 epic fact-catalog 的直接依据。

**Non-Goals:**

- 不做生产能力映射（工具/Skill/智能体能否生产）。
- 不定义契约结构或输出 schema（那是 epic 的 contract-format / output-schema 设计）。
- 清单成稿后不在本变更内增删事实类型；确需补录走 fact-catalog 的补录机制并回溯记录差异。

## Decisions

1. **事实优先**：事实需求从语义表达目标推导，不从工具输出反推。备选（按工具能输出的东西列清单）被否——会把能力缺口固化进需求。
2. **层级由分析汇总得出，不预设**：先收集原始事实需求，再按聚合度归类定层；落稿结论为四层（项目→模块→符号→事实），论证见清单正文（各层小节及"语义表达中的作用"节）。备选（预先设定层级再填内容）被否——会把设计假设冒充调研结论。
3. **一次成稿、有界不扩张（重入例外：2026-10-22 全面重研）**：清单成稿后不新增事实类型；设计阶段确需补录走 fact-catalog 的补录机制并回溯记录差异，不在本变更内反复重开。理由：调研是设计输入不是交付物本身；备选（持续演进的开放清单）被否——epic 无法在其上固化封闭世界目录。**重入授权**：用户于 2026-10-22 明确指示"重新进行语义事实需求调研工作"并选定**全面重研**形态（从零重新归纳，可推翻现有四层结论，更新基准日期与清单正文）——构成 config 规则"重入取决于有强制要求"中的强制要求，本次重入后清单重新成稿，仍适用一次成稿约束。
4. **清单用中文撰写**，与 config.yaml 的 zh 约定一致；SHALL/MUST 等结构关键词保留英文。

## Risks / Trade-offs

- [清单与 epic 后续设计出现偏差] → 清单明确声明其定位是 fact-catalog 的蓝本，epic 设计时允许增删并回溯本清单记录差异。
- [语义词汇随语言生态演进] → 词汇表定位为初版，演进通过 fact-catalog 补录机制承载，不回改已成稿清单。
